# 渲染（`src/render`）

把一帧（`RenderFrame`）画出来：背景、歌词、特效插件、转场与字幕。不决定时间与位置。总览在 `docs/ARCHITECTURE.md`。

## 图层与特效

每帧的固定图层顺序：
`backdrop → 闪光 → world-back → lyrics → world-front → foreground → 反色闪光 → 模糊转场 → 闲置点、字幕、开场、片尾卡 → 结尾淡出 → 帷幕 → screen → handoff`

**特效 → 图层 → 跟随方式**（2.12 统一）：

| 图层 | 特效 | 跟随镜头的方式 |
|---|---|---|
| backdrop：地面 | 各背景的底色与渐层、液态、光斑、哥特、视频／MV | 背景自己的镜头（旋转、缩放），平移视差各自处理（液态、光斑、视频依自己的深度） |
| backdrop：中景（`MID` = 0.6） | 封面、唱片、地面格线、频谱、门框地平线、节拍光环与音箱、碎玻璃板 | 背景镜头 ＋ 统一的中景视差 `midShift`（平移的 0.6 倍）；光环从它出来的东西（封面、唱片、地平线）位置发出，所以一起移动 |
| backdrop：依深度 | 光点、羽毛、背景线条、立体线条、碎块 | 背景镜头 ＋ 依每个元素自己深度的视差 |
| backdrop：深层 | 字形纹样 | 场景里、歌词后方远处（2.17：随镜头移动、缩放、旋转，视差小于歌词） |
| world-back／world-front | 文字残影、歌词框线、字环、星星 | 歌词世界（投影、依远近受力） |
| foreground | 碎玻璃碎片（取自碎玻璃板所在处，和板子同一套背景镜头与中景视差）、哥特锁链、几何前景、前景羽毛、反色几何（最后画：会反转歌词，但不反转字幕、片尾卡和帷幕） | 各自处理 |
| screen | 颗粒、暗角、扫描线、色散、故障 | 固定在屏幕上；随特效视图淡入淡出，结尾淡出时一起淡出 |

**歌词图层在显卡上**（2.13，`render/gpu.ts`）：歌词的绘制程序不变，改画进一个「看起来像 2D 画布」的录制环境。
- 它画的都是图片：字形的模糊阶梯、投影、厚度边、外框，在这个模式下连清晰字形也来自位图（`glyphs.ts` 的 `setAllBitmap`，小字的尺寸阶梯放宽为四分之一个八度）。每一次绘制变成一个带完整变换与不透明度的纹理四边形。
- 位图放进 2048² 的图集（货架式摆放；太大的自成一张纹理），只上传一次。一帧的四边形依原本的绘制顺序，用少数几次实例化绘制画完（预乘 alpha 的 source-over，和画布相同），再一次复制进画面。
- 等待中的四边形各自记得自己的纹理，绘制时才绑定，所以中途上传别的位图也不会取错图。
- 画布只会变大，即时画面和不同尺寸的导出轮流画在它的左上角。
- 没有 WebGL2、或显卡情境遗失时，歌词照原本的方式画在画面上。设置可关闭（`gpuLyrics`）；导出和即时画面用同一种画法。
- 渲染测试逐像素比较两种画法：五种主题各七个时间点，差异只在字形边缘（明显不同的像素约 1%，主要是未唱字的细外框；画错字时会到 3% 以上）。

**距离场字形**（2.22，`glyphs.ts` 的 `sdfGlyph`、`gpu.ts` 的 `sdfQuad`）：在显卡歌词层上，900 px 以下的清晰字形不再用位图。
- 原因：清晰字形的位图依尺寸阶梯（八分之一个八度）、依画法（字面渐层、厚度边、未唱外框）各做一张。镜头穿过一页歌词时字的大小一直跨阶，一秒做上百张，每张在 CPU 上画好再上传，而且就在第一次需要它的那一帧做。压力测试（1080p、密集歌词 30 秒）约 3,000 张；2160p 更有 1,200 张 400～1,200 px 的大字。这是歌词多时卡顿的主因之一。
- 做法：每个字只做一张距离场（每个像素到字形边缘的距离），两级：字小于 400 px 用 128 px 的字身，400～900 px 用 320 px；由一次反锯齿的点阵化加上两次欧氏距离转换算出（Felzenszwalb–Huttenlocher）。着色器依字在屏幕上的大小算出每个像素的覆盖率：填色、由上而下的三色渐层、字形外的外框，全部来自同一张距离场，任何大小都不再重做。
- 900 px 以上的特写仍用位图；模糊的字（景深、投影）仍用模糊阶梯，它本来就与大小无关、每个字只做一次。没有显卡歌词层时，2D 画布照旧。
- 歌曲规划好后的预先绘制改为产生这首歌每个字的距离场（`prewarmSdf`）。
- （2.22.1）距离场分三级：72 px 以下用 48 px 字身，400 px 以下 128 px，900 px 以下 320 px，缩小采样不超过约 1.5 倍。边缘宽度由着色器以屏幕上相邻像素的距离变化率求出（不依赖 CPU 估的字级），过渡 1.3 像素。

**两层叠出的混合**（`glyphs.ts` 的 `layerPair`）：模糊阶梯的两层之间、对焦交接的模糊与清晰之间，都是一层画在另一层上。下层用它所占比例的不透明度，上层取能让字身保持在目标不透明度的值，但不超过比例的三倍。在不透明度为 1 时，只靠两层又要字身精确，数学上做不到连续；以前的公式因此在不透明度刚离开 1、或模糊跨过一阶时，让光晕与阴影一帧内缩小。现在全程连续，代价是不透明度为 1 时换层的中途字身最多平滑地暗约 8%。
- 量测（软件绘制环境）：主线程上做字形与上传的时间减少约七成，新做的字形从 4,756 降到 1,180（剩下的是每字一次的模糊阶梯），不再有「一帧做几十个大字形」的卡顿帧。着色器的运算略多，在这个以 CPU 模拟显卡的环境里看得出来，在实际显卡上可以忽略。
- **显卡内存与上传量**（2.17）：
  - 图集最多 10 页。满了时，清空「最久没用到」的那一页重新填（保留纹理、先清干净），绝不清本帧正在用的页；以前是整个图集砍掉重建，特写沿长词缩放时每帧都重配、重传整个图集。
  - 清晰字形位图在此模式下最大约 640 px（`glyphs.ts` `CAP_GPU`），全部放得进图集页，不再有几十张 1200×1700 的独立纹理；更大的字由它稍微放大。独立纹理改以大小（64 MB）而非张数限制。
  - 每帧新建的大型位图有配额（`glyphFrame`，600 万像素）；超过时先用邻近尺寸已有的那张，下一帧再补做。
  - 量测（4K、特写、「きゃきゃ…」长词进场）：每帧新配置的图集页从 5–6 张降为 0，最重一帧上传从约 18 MP 降为约 8 MP。
- 画布情境遗失（显卡重置）时记录在性能数据里，恢复后立即重画。

**不是数字的值**（2.17.1）：画布遇到带 NaN 的变换、透明度或颜色时会静静地忽略那次绘制，不报错也不变慢，画面停住或变黑。所以：
- `RhythmMap` 读分析时先经过 `repairAnalysis`：拍点须为数字且严格递增、事件与段落与各曲线都是数字、速度与拍号合理。正常的分析原封不动；修过的会记在 `map.repairs`，并在主控台警告。
- 引擎的 `frameAt` 每帧检查镜头、律动、背景镜头与节奏采样，有不是数字的就改用上一个正常帧，并记录字段名称。

**镜头的优先级**（2.17.6）：正在唱的字一定在画面内 > 歌词框在显示期间完整在画面内（`fit.ts`）> 和声。停点只瞄准歌词本身（`boxIn` 默认不含和声）；和声只让镜头最多拉远 15% 来容纳，放不下就超出画面，镜头不会移过去或停在和声上。逐行歌词（整行同时出现）由一个停点框住整行（放得下时），除了第一个词以外不做「先移进画面再滑回」。

**框住歌词框的修正**（`fit.ts`，2.17.5）：在已平滑的路径上直接加减 x、y、远近。歌词框全被放弃、且没有字正在唱时，那一刻不做修正（以前会量一个空的范围，加进 log 0 与 ∞·0，产生两秒多 NaN 的镜头）；不是有限数字的修正一律不加。

**详细调试日志**（2.17.1，`engine/debug.ts`，设置「详细调试日志」）：打开时记录每一帧（时间、画面、画布大小、耗时、镜头与律动、节奏采样、显卡歌词数字、不是数字的字段），每秒四次把画布内容读回 16×9 像素判断画面是否停住或变黑，并记录事件（情境遗失、错误与警告、分析修正、换歌、换画面）。保留最近约 12000 帧，可以导出成文字档。关闭时只剩 `frameAt` 的检查。

**播放时钟**（2.14，`engine/audio.ts`）：标准输出的时间不再直接读 `AudioContext.currentTime`——它以一个音频缓冲区为单位跳动（1024 样本约 23 ms，许多设备 10 ms），而且比扬声器实际发声早一个输出延迟，所以画面常常一两帧不动、接着跳一下，看起来比实际帧数低。改用 `getOutputTimestamp()`（哪个 context 时间在哪个时刻离开扬声器）加上之后经过的时间，再平滑成一条不倒退的时钟（差距小时几帧内追上，超过 50 ms 直接跳到）。Hi-Fi 输出本来就是这样做的。

**起播**（2.14，`app/playback/player.ts`）：
- 已分析过的歌，场景（断词、字体、规划）依分析记录的长度先创建，同时解码音频；解码好了直接换上（长度差超过 50 ms 才重新计算时间）。
- 音频环境与断词字典在启动后的闲置时间先准备好，第一次播放不必等。
- 预备的歌最多三首（这首、下一首、再一首），每首都带着解码后的音频。
- 每次起播的各阶段耗时（读档与解码、节奏、创建场景：封面、断词、字体、规划，以及显示）记在 `app/playback/trace.ts`，性能数据里显示上一次的分段。

**分辨率自动调整**：改变分辨率会让画面上的每个字形以新尺寸重做；以前在一帧内切换，可能卡住一秒并清空画布。现在先在闲置时间把接下来几秒要用的字形以新尺寸做好再切换；切换后至少静置 6 秒（降）或 12 秒（升），不会来回跳动。超过 150 ms 的帧、以及帧与帧之间超过 250 ms 的空档，连同当时新做的字形数、是否改了分辨率、是否换了规划，记在 `Engine.stalls`，性能数据显示两分钟内最长的一次。

**背景分析让路**：特效歌词在画面上且正在播放时，音乐库的背景分析在两首歌之间暂停（画面独用显卡），回到其他页面或暂停时继续。

**Hi-Fi 设备**：选定的设备不在（拔掉、停用）时，原生播放器改用系统默认设备并通知页面一次；它回来后再改回。播放中设备消失时，从同一位置在可用的设备上继续，不再停下来要求重新选择。

**跟上屏幕的更新率**（2.21.1 检查）：界面与绘制不假设 60 Hz。
- 所有逐帧的动画都以经过的时间计算（弹簧、海报墙的画廊、音乐库的频谱小图标、拖动排序时的边缘滚动），在 60、144、240 Hz 下速度一样；不用固定间隔的计时器驱动动画。
- 播放页展开与收起时不重画内容：页面与它的光各是一个「裁切框」（以 transform 下移，高度为露出的部分）包着一个反向移回的图层（`layers.ts` 的 `cutBox`）；封面的两层阴影（迷你封面的、播放页的）各画一次，以不透明度交替；圆角在封面里不绘制任何东西的裁切层上。以 clip-path、box-shadow、border-radius 逐帧改变，会让整页（含 70px 模糊的封面光晕）每帧重画。画面的 canvas 保留 clip-path（canvas 不因此重画），而且不能加 `will-change`（会让展开中的画面消失）。
- 每帧写入的样式只在值改变时才写（播放页的逐字亮度、进度的时间文字），否则浏览器每帧重算整行。
- 预先绘制（`startBake` 的重步骤）以「这首歌一帧实际的时间」判断空档，等候超过 1.5 秒就在两帧之间执行；以前要求 16 ms 的空档，高更新率下永远等不到。
- 量测方式：解除帧率上限（`--disable-frame-rate-limit --disable-gpu-vsync`）后看每个场景的帧率、每帧的脚本／样式／版面时间，并以 DevTools 追踪看每个图层的点阵化时间。

**性能数据**（`PROFILE`、`Engine.perf`）：打开后每帧记录背景、特效、歌词、字幕与转场、屏幕特效各花的页面时间，以及实际帧率，平滑后显示在特效歌词左上角（`app/views/PerfHud.tsx`）。这些是页面这边的时间；显卡之后的工作反映在帧率上。

**效果插件接口**：
```ts
interface Effect<P> {
  id: string; layer: Layer; label: string;           // label 为 i18n 键
  params: ParamSchema<P>;                            // 界面依此自动生成控制项
  plan?(ctx: PlanContext, p: P): unknown;            // 规划时（一次）：事件、几何
  prepare?(ctx: PrepareContext, p: P, plan: unknown): void;   // 资源：精灵图、路径（依调色板缓存）
  draw(g: CanvasRenderingContext2D, f: RenderFrame, p: P, plan: unknown): void;
}
```
新增效果 = 新增一个文件并 `register()`；主题只是「背景 + 效果清单 + 参数」，不改核心。

## 转场的样子（`render/transitions.ts`，3.5.0）

导演的段落（passages）给出每一帧在转场里的位置（`transPhase`：强度 k、在切点之前或之后、那一侧走了多少）。渲染器依风格的 `transFx` 从登记表取出一种转场画在完成的画面上：

| id | 名字 | 做法 |
| --- | --- | --- |
| `frost` | 柔焦（默认） | Cadenza 自己的全画面高斯模糊（`post.ts` 的 `drawTransition`），省力模式改用双重滤波、最省力只染色 |
| `blur` | 模糊淡出（Folia） | Folia 商籁的 fast blur：最多 14 px 模糊，切点前淡入背景色、切点后回来 |
| `fade` | 淡出（Folia） | Folia 的淡出：只有染色 |
| `glitch` | 撕裂（Folia） | Folia 的单色撕裂：与它的着色器同样的哈希、14／58 条带与位移，每侧跳 14 步；切点前最后 14% 淡入背景色 |

Folia 的三种用它自己的缓动（`easeSonnetInOut`）与数字。**新增一种转场**：`registerTransition({ id, label, draw(g, f, k, phase) })`，字典加 `trf.<id>`，设置页的菜单自动列出。

## 背景（backdrop）

背景是 `kind: 'backdrop'` 的特效，与其他特效同一个登记表（`effects/registry.ts`），参数由 `params` 声明，界面依此产生控制项；参数可以带 `showIf: [键, 值]`，只在另一个参数是某值时显示。

- Cadenza 自己的：封面、液态、光斑、哥特、唱片、视频／MV、纯色等（`effects/backdrops.ts`、`cover.ts`、`ambient.ts`…）。
- Folia 的五种（`effects/foliaBackdrops.ts`，3.4.0）：通用 `f-common`、隐现 `f-latent`、空 `f-sora`、莫奈 `f-monet`、漫游 `f-nomand`。画法在 `src/folia/backgrounds.ts`（上游的纯计算部分原样抽出），漫游的五种效果用 Paper 着色器（`src/folia/paper.ts`）。颜色只取外观的颜色与封面取色，不用 Folia 自己生成的主题色。频段与歌曲种子由 `frameOf` 从节奏分析读出。

## 正在播放页的背景（3.5.0）

正在播放页的背景也是引擎画的（环境视图）。默认是 `ambient`（封面的流动色场）；用户可在正在播放页的设置改成任一种 Folia 背景（`npLyr.bg`，经 `engine.setPageBackdrop`）。渲染器在环境视图画 `pageFx`，参数沿用该背景在特效歌词里的设置（`st.fxp`）。正在播放页的歌词只由界面画（`ui/NpLyrics.tsx`），不接任何歌词引擎。

## 歌词引擎：导演之外的画法

风格可以带 `engine`（`theme/style.ts`）：没有时由导演规划、`lyrics.ts` 画；`sonnet`（商籁）或 `tempera`（凝彩）时由 `render/engines.ts` 交给 `src/folia/engines/` 的执行层，画在同一个背景之上，屏幕特效照常叠上去。引擎参数（`ENGINE_PARAMS`）有各自的与共用的（`SHARED_PARAMS`，例如「用 Folia 自己的分词」），改到会重建的参数列在重建键里。细节见 `docs/FOLIA.md`。
