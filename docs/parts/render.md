# 渲染（`src/render`）

把一幀（`RenderFrame`）畫出來：背景、歌詞、特效外掛、轉場與字幕。不決定時間與位置。總覽在 `docs/ARCHITECTURE.md`。

## 圖層與特效

每幀的固定圖層順序：
`backdrop → 閃光 → world-back → lyrics → world-front → foreground → 反色閃光 → 模糊轉場 → 閒置點、字幕、開場、片尾卡 → 結尾淡出 → 帷幕 → screen → handoff`

**特效 → 圖層 → 跟隨方式**（2.12 統一）：

| 圖層 | 特效 | 跟隨鏡頭的方式 |
|---|---|---|
| backdrop：地面 | 各背景的底色與漸層、液態、光斑、哥特、影片／MV | 背景自己的鏡頭（旋轉、縮放），平移視差各自處理（液態、光斑、影片依自己的深度） |
| backdrop：中景（`MID` = 0.6） | 封面、唱片、地面格線、頻譜、門框地平線、節拍光環與音箱、碎玻璃板 | 背景鏡頭 ＋ 統一的中景視差 `midShift`（平移的 0.6 倍）；光環從它出來的東西（封面、唱片、地平線）位置發出，所以一起移動 |
| backdrop：依深度 | 光點、羽毛、背景線條、立體線條、碎塊 | 背景鏡頭 ＋ 依每個元素自己深度的視差 |
| backdrop：深層 | 字形紋樣 | 場景裡、歌詞後方遠處（2.17：隨鏡頭移動、縮放、旋轉，視差小於歌詞） |
| world-back／world-front | 文字殘影、歌詞框線、字環、星星 | 歌詞世界（投影、依遠近受力） |
| foreground | 碎玻璃碎片（取自碎玻璃板所在處，和板子同一套背景鏡頭與中景視差）、哥特鎖鏈、幾何前景、前景羽毛、反色幾何（最後畫：會反轉歌詞，但不反轉字幕、片尾卡和帷幕） | 各自處理 |
| screen | 顆粒、暗角、掃描線、色散、故障 | 固定在螢幕上；隨特效視圖淡入淡出，結尾淡出時一起淡出 |

**歌詞圖層在顯示卡上**（2.13，`render/gpu.ts`）：歌詞的繪製程式不變，改畫進一個「看起來像 2D 畫布」的錄製環境。
- 它畫的都是圖片：字形的模糊階梯、投影、厚度邊、外框，在這個模式下連清晰字形也來自點陣圖（`glyphs.ts` 的 `setAllBitmap`，小字的尺寸階梯放寬為四分之一個八度）。每一次繪製變成一個帶完整變換與不透明度的貼圖四邊形。
- 點陣圖放進 2048² 的圖集（貨架式擺放；太大的自成一張貼圖），只上傳一次。一幀的四邊形依原本的繪製順序，用少數幾次實例化繪製畫完（預乘 alpha 的 source-over，和畫布相同），再一次複製進畫面。
- 等待中的四邊形各自記得自己的貼圖，繪製時才綁定，所以中途上傳別的點陣圖也不會取錯圖。
- 畫布只會變大，即時畫面和不同尺寸的匯出輪流畫在它的左上角。
- 沒有 WebGL2、或顯示卡情境遺失時，歌詞照原本的方式畫在畫面上。設定可關閉（`gpuLyrics`）；匯出和即時畫面用同一種畫法。
- 渲染測試逐像素比較兩種畫法：五種主題各七個時間點，差異只在字形邊緣（明顯不同的像素約 1%，主要是未唱字的細外框；畫錯字時會到 3% 以上）。

**距離場字形**（2.22，`glyphs.ts` 的 `sdfGlyph`、`gpu.ts` 的 `sdfQuad`）：在顯示卡歌詞層上，900 px 以下的清晰字形不再用點陣圖。
- 原因：清晰字形的點陣圖依尺寸階梯（八分之一個八度）、依畫法（字面漸層、厚度邊、未唱外框）各做一張。鏡頭穿過一頁歌詞時字的大小一直跨階，一秒做上百張，每張在 CPU 上畫好再上傳，而且就在第一次需要它的那一幀做。壓力測試（1080p、密集歌詞 30 秒）約 3,000 張；2160p 更有 1,200 張 400～1,200 px 的大字。這是歌詞多時卡頓的主因之一。
- 做法：每個字只做一張距離場（每個像素到字形邊緣的距離），兩級：字小於 400 px 用 128 px 的字身，400～900 px 用 320 px；由一次反鋸齒的點陣化加上兩次歐氏距離轉換算出（Felzenszwalb–Huttenlocher）。著色器依字在螢幕上的大小算出每個像素的覆蓋率：填色、由上而下的三色漸層、字形外的外框，全部來自同一張距離場，任何大小都不再重做。
- 900 px 以上的特寫仍用點陣圖；模糊的字（景深、投影）仍用模糊階梯，它本來就與大小無關、每個字只做一次。沒有顯示卡歌詞層時，2D 畫布照舊。
- 歌曲規劃好後的預先繪製改為產生這首歌每個字的距離場（`prewarmSdf`）。
- （2.22.1）距離場分三級：72 px 以下用 48 px 字身，400 px 以下 128 px，900 px 以下 320 px，縮小取樣不超過約 1.5 倍。邊緣寬度由著色器以螢幕上相鄰像素的距離變化率求出（不依賴 CPU 估的字級），過渡 1.3 像素。

**兩層疊出的混合**（`glyphs.ts` 的 `layerPair`）：模糊階梯的兩層之間、對焦交接的模糊與清晰之間，都是一層畫在另一層上。下層用它所佔比例的不透明度，上層取能讓字身保持在目標不透明度的值，但不超過比例的三倍。在不透明度為 1 時，只靠兩層又要字身精確，數學上做不到連續；以前的公式因此在不透明度剛離開 1、或模糊跨過一階時，讓光暈與陰影一幀內縮小。現在全程連續，代價是不透明度為 1 時換層的中途字身最多平滑地暗約 8%。
- 量測（軟體繪製環境）：主執行緒上做字形與上傳的時間減少約七成，新做的字形從 4,756 降到 1,180（剩下的是每字一次的模糊階梯），不再有「一幀做幾十個大字形」的卡頓幀。著色器的運算略多，在這個以 CPU 模擬顯示卡的環境裡看得出來，在實際顯示卡上可以忽略。
- **顯示卡記憶體與上傳量**（2.17）：
  - 圖集最多 10 頁。滿了時，清空「最久沒用到」的那一頁重新填（保留貼圖、先清乾淨），絕不清本幀正在用的頁；以前是整個圖集砍掉重建，特寫沿長詞縮放時每幀都重配、重傳整個圖集。
  - 清晰字形點陣圖在此模式下最大約 640 px（`glyphs.ts` `CAP_GPU`），全部放得進圖集頁，不再有幾十張 1200×1700 的獨立貼圖；更大的字由它稍微放大。獨立貼圖改以大小（64 MB）而非張數限制。
  - 每幀新建的大型點陣圖有額度（`glyphFrame`，600 萬像素）；超過時先用鄰近尺寸已有的那張，下一幀再補做。
  - 量測（4K、特寫、「きゃきゃ…」長詞進場）：每幀新配置的圖集頁從 5–6 張降為 0，最重一幀上傳從約 18 MP 降為約 8 MP。
- 畫布情境遺失（顯示卡重置）時記錄在效能資料裡，恢復後立即重畫。

**不是數字的值**（2.17.1）：畫布遇到帶 NaN 的變換、透明度或顏色時會靜靜地忽略那次繪製，不報錯也不變慢，畫面停住或變黑。所以：
- `RhythmMap` 讀分析時先經過 `repairAnalysis`：拍點須為數字且嚴格遞增、事件與段落與各曲線都是數字、速度與拍號合理。正常的分析原封不動；修過的會記在 `map.repairs`，並在主控台警告。
- 引擎的 `frameAt` 每幀檢查鏡頭、律動、背景鏡頭與節奏取樣，有不是數字的就改用上一個正常幀，並記錄欄位名稱。

**鏡頭的優先順序**（2.17.6）：正在唱的字一定在畫面內 > 歌詞框在顯示期間完整在畫面內（`fit.ts`）> 和聲。停點只瞄準歌詞本身（`boxIn` 預設不含和聲）；和聲只讓鏡頭最多拉遠 15% 來容納，放不下就超出畫面，鏡頭不會移過去或停在和聲上。逐行歌詞（整行同時出現）由一個停點框住整行（放得下時），除了第一個詞以外不做「先移進畫面再滑回」。

**框住歌詞框的修正**（`fit.ts`，2.17.5）：在已平滑的路徑上直接加減 x、y、遠近。歌詞框全被放棄、且沒有字正在唱時，那一刻不做修正（以前會量一個空的範圍，加進 log 0 與 ∞·0，產生兩秒多 NaN 的鏡頭）；不是有限數字的修正一律不加。

**詳細除錯日誌**（2.17.1，`engine/debug.ts`，設定「詳細除錯日誌」）：開啟時記錄每一幀（時間、畫面、畫布大小、耗時、鏡頭與律動、節奏取樣、顯示卡歌詞數字、不是數字的欄位），每秒四次把畫布內容讀回 16×9 像素判斷畫面是否停住或變黑，並記錄事件（情境遺失、錯誤與警告、分析修正、換歌、換畫面）。保留最近約 12000 幀，可以匯出成文字檔。關閉時只剩 `frameAt` 的檢查。

**播放時鐘**（2.14，`engine/audio.ts`）：標準輸出的時間不再直接讀 `AudioContext.currentTime`——它以一個音訊緩衝區為單位跳動（1024 樣本約 23 ms，許多裝置 10 ms），而且比喇叭實際發聲早一個輸出延遲，所以畫面常常一兩幀不動、接著跳一下，看起來比實際幀數低。改用 `getOutputTimestamp()`（哪個 context 時間在哪個時刻離開喇叭）加上之後經過的時間，再平滑成一條不倒退的時鐘（差距小時幾幀內追上，超過 50 ms 直接跳到）。Hi-Fi 輸出本來就是這樣做的。

**起播**（2.14，`app/playback/player.ts`）：
- 已分析過的歌，場景（斷詞、字體、規劃）依分析記錄的長度先建立，同時解碼音訊；解碼好了直接換上（長度差超過 50 ms 才重新計算時間）。
- 音訊環境與斷詞字典在啟動後的閒置時間先準備好，第一次播放不必等。
- 預備的歌最多三首（這首、下一首、再一首），每首都帶著解碼後的音訊。
- 每次起播的各階段耗時（讀檔與解碼、節奏、建立場景：封面、斷詞、字體、規劃，以及顯示）記在 `app/playback/trace.ts`，效能數據裡顯示上一次的分段。

**解析度自動調整**：改變解析度會讓畫面上的每個字形以新尺寸重做；以前在一幀內切換，可能卡住一秒並清空畫布。現在先在閒置時間把接下來幾秒要用的字形以新尺寸做好再切換；切換後至少靜置 6 秒（降）或 12 秒（升），不會來回跳動。超過 150 ms 的幀、以及幀與幀之間超過 250 ms 的空檔，連同當時新做的字形數、是否改了解析度、是否換了規劃，記在 `Engine.stalls`，效能數據顯示兩分鐘內最長的一次。

**背景分析讓路**：特效歌詞在畫面上且正在播放時，音樂庫的背景分析在兩首歌之間暫停（畫面獨用顯示卡），回到其他頁面或暫停時繼續。

**Hi-Fi 裝置**：選定的裝置不在（拔掉、停用）時，原生播放器改用系統預設裝置並通知頁面一次；它回來後再改回。播放中裝置消失時，從同一位置在可用的裝置上繼續，不再停下來要求重新選擇。

**跟上螢幕的更新率**（2.21.1 檢查）：介面與繪製不假設 60 Hz。
- 所有逐幀的動畫都以經過的時間計算（彈簧、海報牆的畫廊、音樂庫的頻譜小圖示、拖曳排序時的邊緣捲動），在 60、144、240 Hz 下速度一樣；不用固定間隔的計時器驅動動畫。
- 播放頁展開與收起時不重畫內容：頁面與它的光各是一個「裁切框」（以 transform 下移，高度為露出的部分）包著一個反向移回的圖層（`layers.ts` 的 `cutBox`）；封面的兩層陰影（迷你封面的、播放頁的）各畫一次，以不透明度交替；圓角在封面裡不繪製任何東西的裁切層上。以 clip-path、box-shadow、border-radius 逐幀改變，會讓整頁（含 70px 模糊的封面光暈）每幀重畫。畫面的 canvas 保留 clip-path（canvas 不因此重畫），而且不能加 `will-change`（會讓展開中的畫面消失）。
- 每幀寫入的樣式只在值改變時才寫（播放頁的逐字亮度、進度的時間文字），否則瀏覽器每幀重算整行。
- 預先繪製（`startBake` 的重步驟）以「這首歌一幀實際的時間」判斷空檔，等候超過 1.5 秒就在兩幀之間執行；以前要求 16 ms 的空檔，高更新率下永遠等不到。
- 量測方式：解除幀率上限（`--disable-frame-rate-limit --disable-gpu-vsync`）後看每個場景的幀率、每幀的腳本／樣式／版面時間，並以 DevTools 追蹤看每個圖層的點陣化時間。

**效能數據**（`PROFILE`、`Engine.perf`）：開啟後每幀記錄背景、特效、歌詞、字幕與轉場、螢幕特效各花的頁面時間，以及實際幀率，平滑後顯示在特效歌詞左上角（`app/views/PerfHud.tsx`）。這些是頁面這邊的時間；顯示卡之後的工作反映在幀率上。

**效果外掛介面**：
```ts
interface Effect<P> {
  id: string; layer: Layer; label: string;           // label 為 i18n 鍵
  params: ParamSchema<P>;                            // 介面依此自動生成控制項
  plan?(ctx: PlanContext, p: P): unknown;            // 規劃時（一次）：事件、幾何
  prepare?(ctx: PrepareContext, p: P, plan: unknown): void;   // 資源：精靈圖、路徑（依調色盤快取）
  draw(g: CanvasRenderingContext2D, f: RenderFrame, p: P, plan: unknown): void;
}
```
新增效果 = 新增一個檔案並 `register()`；主題只是「背景 + 效果清單 + 參數」，不改核心。

## 轉場的樣子（`render/transitions.ts`，3.5.0）

導演的段落（passages）給出每一幀在轉場裡的位置（`transPhase`：強度 k、在切點之前或之後、那一側走了多少）。渲染器依風格的 `transFx` 從登記表取出一種轉場畫在完成的畫面上：

| id | 名字 | 做法 |
| --- | --- | --- |
| `frost` | 柔焦（預設） | Cadenza 自己的全畫面高斯模糊（`post.ts` 的 `drawTransition`），省力模式改用雙重濾波、最省力只染色 |
| `blur` | 模糊淡出（Folia） | Folia 商籟的 fast blur：最多 14 px 模糊，切點前淡入背景色、切點後回來 |
| `fade` | 淡出（Folia） | Folia 的淡出：只有染色 |
| `glitch` | 撕裂（Folia） | Folia 的單色撕裂：與它的著色器同樣的雜湊、14／58 條帶與位移，每側跳 14 步；切點前最後 14% 淡入背景色 |

Folia 的三種用它自己的緩動（`easeSonnetInOut`）與數字。**新增一種轉場**：`registerTransition({ id, label, draw(g, f, k, phase) })`，字典加 `trf.<id>`，設定頁的選單自動列出。

## 背景（backdrop）

背景是 `kind: 'backdrop'` 的特效，與其他特效同一個登記表（`effects/registry.ts`），參數由 `params` 宣告，介面依此產生控制項；參數可以帶 `showIf: [鍵, 值]`，只在另一個參數是某值時顯示。

- Cadenza 自己的：封面、液態、光斑、哥特、唱片、影片／MV、純色等（`effects/backdrops.ts`、`cover.ts`、`ambient.ts`…）。
- Folia 的五種（`effects/foliaBackdrops.ts`，3.4.0）：通用 `f-common`、隱現 `f-latent`、空 `f-sora`、莫奈 `f-monet`、漫遊 `f-nomand`。畫法在 `src/folia/backgrounds.ts`（上游的純計算部分原樣抽出），漫遊的五種效果用 Paper 著色器（`src/folia/paper.ts`）。顏色只取外觀的顏色與封面取色，不用 Folia 自己生成的主題色。頻段與歌曲種子由 `frameOf` 從節奏分析讀出。

## 正在播放頁的背景（3.5.0）

正在播放頁的背景也是引擎畫的（環境視圖）。預設是 `ambient`（封面的流動色場）；使用者可在正在播放頁的設定改成任一種 Folia 背景（`npLyr.bg`，經 `engine.setPageBackdrop`）。渲染器在環境視圖畫 `pageFx`，參數沿用該背景在特效歌詞裡的設定（`st.fxp`）。正在播放頁的歌詞只由介面畫（`ui/NpLyrics.tsx`），不接任何歌詞引擎。

## 歌詞引擎：導演之外的畫法

風格可以帶 `engine`（`theme/style.ts`）：沒有時由導演規劃、`lyrics.ts` 畫；`sonnet`（商籟）或 `tempera`（凝彩）時由 `render/engines.ts` 交給 `src/folia/engines/` 的執行層，畫在同一個背景之上，螢幕特效照常疊上去。引擎參數（`ENGINE_PARAMS`）有各自的與共用的（`SHARED_PARAMS`，例如「用 Folia 自己的分詞」），改到會重建的參數列在重建鍵裡。細節見 `docs/FOLIA.md`。
