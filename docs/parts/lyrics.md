# 歌詞（`src/lyrics`、`src/text`）

歌詞模型是全專案唯一的文字來源：播放列、正在播放頁、特效歌詞、Folia 風格與空間介面都從它讀。這裡是規則的細節；總覽在 `docs/ARCHITECTURE.md`。

`lyrics` 只需要節拍來排詞，所以它定義了自己的最小介面 `BeatGrid`（速度、拍長、對齊到格線）。`RhythmMap` 正好符合這個介面，lyrics 因此不必引用 rhythm。

**歌詞來源與格式**（2.15）：
- 讀取順序：歌曲旁的 `.ttml` → 檔案標籤裡名為 TTML 的欄位（Vorbis `TTML`、ID3 `TXXX:TTML`、MP4 `----:com.apple.iTunes:TTML`）→ 歌曲旁的 `.lrc` → 檔案內嵌歌詞。在程式裡編輯過歌詞的歌（存成 LRC），之後改讀 LRC（`overrides.preferLrc`）。
- `lyrics/ttml.ts` 把 TTML 轉成和 LRC 一樣的解析結果（`parseLyrics` 依內容自動選擇）：
  - 逐行或逐音節（`<span begin end>`）的時間；
  - `ttm:role="x-bg"` 背景人聲變成和聲；
  - `<head>` 裡的 `translations` 是翻譯（`subs`），`transliterations` 是讀音（`reads`，和翻譯分開存）；
  - 沒有 key、時間和前一行完全相同的 `<p>` 是那一行的翻譯，「待翻译」之類的佔位文字略過；
  - 每一行帶著自己的結束時間（`RawLine.end`），和下一行重疊時照樣顯示到結束。
- 編輯器把 TTML 轉成 LRC 顯示（`ttmlToLrc`），匯入 `.ttml` 檔則照原樣存成 `.ttml`。

**逐行歌詞**：只有整行時間的歌詞整行出現、整行唱完（不再估算逐字時間來點亮）；鏡頭仍依估算的位置沿著這一行移動。播放頁整行一起亮起；第一句開始前不亮任何一句。

**時間重疊**：歌詞本身給了字的結束時間（`Word.endGiven`），而它晚於下一個字的開始時，鏡頭等它唱完才移到下一個字（最多 2 秒），這個字也唱完才算「唱過」；下一個字照常進場。播放頁裡，與上一行重疊的行等上一行結束才成為當前行，但它的字在這之前就照常亮起。

**原詞空格**：每個詞記著原詞在它之後是否有空格（`gap`），以及跨過原詞空格的詞要顯示的樣子（`disp`）；斷詞、使用者分詞和依唱法合併都會帶著它。播放頁照原詞的空格顯示，不再用分詞的位置。

**頁面清理**：同一頁最多保留的量、以及何時快速清畫面，都改以「分詞後的詞數＋換行數」計算（`pageUnits`；`PAGE_UNITS` 12、`CROWD_UNITS` 20），不再以行數計算：短句多的頁面能多留幾行，長句少留。

**翻譯與讀音的顯示**（2.16，`lyrics/subs.ts`）：播放頁和特效歌詞的小字幕都由 `subLines` 決定顯示什麼：
- 先翻譯、後讀音（和 AMLL、Apple Music 相同的順序），讀音比翻譯淡；
- 翻譯裡括號中的部分另起一行，以和聲的樣式顯示（較小、較淡）；
- 和原句相同的讀音不顯示（例如英文歌的「讀音」就是原句）；播放頁設定「顯示讀音」可以整個關掉讀音；
- 沒有標明讀音的 LRC，假名歌詞下方那一行如果全是羅馬拼音（`looksRomaji`），當成讀音而不是翻譯。

**和聲與鏡頭**（2.16）：鏡頭取景框（`layout.ts` `boxIn`）把每個詞的和聲（`harmBox`，畫在詞的右下方、0.52 倍大）也算進去，和聲不再落在畫面外；碰撞檢查仍只看詞本身。

**2.17 的歌詞與鏡頭規則**：
- **括號一律是和聲**：原詞、翻譯、讀音裡的全形或半形括號內容都當作和聲顯示（讀音的括號也一樣：`subLines`）。
- **逐行歌詞的和聲**整行一起出現、一起亮起，不再依估算的逐字時間掃過（`model.ts`：和聲時間取整行開始）。
- **和聲不擋換行與運鏡**：TTML 的行結束取主唱最後一個音節（背景人聲延續不算）；LRC 和聲之後的空時間戳只結束和聲，不算主唱那個字的結束。所以播放頁換行和鏡頭「上一句沒唱完不走」只看主唱。
- **上下平衡**：「流動」的字往上和往下的機率相同（新增 above／climb），行也一樣；碰撞時往原本那一側推開，不再只往下。
- **滾筒**：重複得比半圈稍快時也觸發，滾動時間縮短（最短為原本的一半、不少於 0.4 秒），彈簧和呼吸也相應減輕（`Roll.dur`、`PWord.rollD`）。
- **漂浮（hover＋圓心）**：鏡頭整行一起框住（放得進稍微拉遠的畫面時），每一行比前一行更靠近鏡頭，唱過的行往後退、變小，不會再比正在唱的行大兩倍而衝出畫面。
- **特寫**：入場時間減半（`enter` 0.12）。
- **結尾的律動**：拍點的擺動以落拍時的音量決定強度，擺動開始後自然跑完；以前整段擺動乘上「現在」的音量，伴奏一弱就被硬拉回。音樂結束後的收束改為 0.8 秒的平滑曲線。

**分詞規則層**（`lyrics/rules.ts`）：在最終分詞（依唱法合併之後）上逐行套用規則，規則可以把詞標為「突出」（`lift`：放大倍數、拉近的縱深）；排版依標記放大並把它放在比同一行前面所有詞更近的位置，所以也畫在它們上面。新增規則只要在 `WORD_RULES` 加一條。第一條：句尾單獨一個漢字（前面有漢字）放大 1.2 倍並拉近。

**純音樂**：標記為純音樂的歌，特效歌詞裡不出現任何歌詞文字（也不把歌名當成歌詞）；播放頁的歌詞處固定顯示「純音樂 請欣賞」。

**詞怎麼切**：分詞器（`spacing.ts`：中文 jieba、日文 BudouX、其他 ICU）只給出「可以切的位置」，詞從不被切開；真正在哪裡切由唱法決定（`phrasing.ts`，在 `buildLyrics` 一開始套用）。逐字時間的歌詞：只有歌手停頓的地方才切——下一個詞明顯比這句的節奏晚到（至少半拍、這句一般字距的 1.8 倍、0.22 秒三者取大），或前一個詞有結束時間、停在下一個詞之前（至少 0.2 拍、0.12 秒）；其餘連著唱的詞合成一個。只有整句時間的歌詞：看分離出的人聲（節奏分析的 `voice`，`rhythm/neural/vocals.ts`：HTDemucs 人聲軌與鼓聲軌同一輪分離，每秒 50 格、0 無聲到 1 這首歌唱得響的程度；沒有人聲的歌為空）——這句時間內人聲低於 0.35 的地方是停頓，短於一口氣（0.16 秒或 0.3 拍取大）的不算；字按各段唱的長度分配，每個停頓取最近的分詞邊界（`voiceCuts`）；一口氣唱完的整句合成一個（仍受 6 字上限）。沒有人聲資料時（沒有分離、DSP 引擎、分析未完成），只把單獨一個字併到旁邊的詞。一個詞最多 `PHRASE_MAX`（6）個字。只合併中文和日文的詞；英文等有空格的詞、韓文、標點、和聲、緊接著重複的詞（滾筒場景用）、使用者自己改過斷詞的句子都不動；句子本身從不合併或拆開。分詞編輯頁顯示的是合併後的結果，存檔時和它相同的句子不算手動修改。
