# 歌词（`src/lyrics`、`src/text`）

歌词模型是全项目唯一的文字来源：播放列、正在播放页、特效歌词、Folia 风格与空间界面都从它读。这里是规则的细节；总览在 `docs/ARCHITECTURE.md`。

`lyrics` 只需要节拍来排词，所以它定义了自己的最小接口 `BeatGrid`（速度、拍长、对齐到格线）。`RhythmMap` 正好符合这个接口，lyrics 因此不必引用 rhythm。

## 歌词来源、编辑视图与播放

- 主进程枚举同一曲目的内嵌和外置来源，并提供字段身份、格式、修订及写入能力。播放选择优先采用用户明确保存的来源，其次采用 TTML 和其他已有来源。历史本地 LRC 选择在读库时迁移为显式来源。不同来源的文本可以独立查看。临时播放组合只对当前视觉会话生效。
- 播放层仍使用 `parseLyrics`，识别逐行、逐字、背景人声、翻译和音译。播放解析只生成画面需要的投影，原始文档在编辑过程中独立保留。
- TTML 的按行编辑操作原始 XML 中的对应节点，保留词间空白、字级时间、注释、未知扩展和未修改的语言轨。高级 XML 模式用于编辑其他方言和源码结构。保存前检查 XML；语义映射不明确的批量修改留待人工确认。
- 增强 LRC 迁移使用原文、整体时间偏移、行序及重复出现的时间差生成候选。置信度不足的条目可人工指定目标。合并时写入指定语言的 Apple TTML 轨，与其他语言及音译轨并存。同语言已有条目保留，旧 LRC 保留为独立来源。
- 所有写入显式选择目标。草稿按曲目、来源、修订存储，与播放器状态、编辑模式和界面路由分离。主进程校验权限、文件版本和字段修订，文本导出经保存对话框。文件标签更新保留可验证的音频身份，删除前保留外部恢复副本。
- 字段矩阵、写入校验和后台任务边界见 [G5.5-R](../G55-R.md)。

**逐行歌词**：只有整行时间的歌词整行出现、整行唱完（不再估算逐字时间来点亮）；镜头仍依估算的位置沿着这一行移动。播放页整行一起亮起；第一句开始前不亮任何一句。

**时间重叠**：歌词本身给了字的结束时间（`Word.endGiven`），而它晚于下一个字的开始时，镜头等它唱完才移到下一个字（最多 2 秒），这个字也唱完才算「唱过」；下一个字照常进场。播放页里，与上一行重叠的行等上一行结束才成为当前行，但它的字在这之前就照常亮起。

**原词空格**：每个词记着原词在它之后是否有空格（`gap`），以及跨过原词空格的词要显示的样子（`disp`）；断词、用户分词和依唱法合并都会带着它。播放页照原词的空格显示，不再用分词的位置。

**页面清理**：同一页最多保留的量、以及何时快速清画面，都改以「分词后的词数＋换行数」计算（`pageUnits`；`PAGE_UNITS` 12、`CROWD_UNITS` 20），不再以行数计算：短句多的页面能多留几行，长句少留。

**翻译与读音的显示**（2.16，`lyrics/subs.ts`）：播放页和特效歌词的小字幕都由 `subLines` 决定显示什么：
- 先翻译、后读音（和 AMLL、Apple Music 相同的顺序），读音比翻译淡；
- 翻译里括号中的部分另起一行，以和声的样式显示（较小、较淡）；
- 和原句相同的读音不显示（例如英文歌的「读音」就是原句）；播放页设置「显示读音」可以整个关掉读音；
- 没有标明读音的 LRC，假名歌词下方那一行如果全是罗马拼音（`looksRomaji`），当成读音而不是翻译。

**和声与镜头**（2.16）：镜头取景框（`layout.ts` `boxIn`）把每个词的和声（`harmBox`，画在词的右下方、0.52 倍大）也算进去，和声不再落在画面外；碰撞检查仍只看词本身。

**2.17 的歌词与镜头规则**：
- **括号一律是和声**：原词、翻译、读音里的全角或半角括号内容都当作和声显示（读音的括号也一样：`subLines`）。
- **逐行歌词的和声**整行一起出现、一起亮起，不再依估算的逐字时间扫过（`model.ts`：和声时间取整行开始）。
- **和声不挡换行与运镜**：TTML 的行结束取主唱最后一个音节（背景人声延续不算）；LRC 和声之后的空时间戳只结束和声，不算主唱那个字的结束。所以播放页换行和镜头「上一句没唱完不走」只看主唱。
- **上下平衡**：「流动」的字往上和往下的概率相同（新增 above／climb），行也一样；碰撞时往原本那一侧推开，不再只往下。
- **滚筒**：重复得比半圈稍快时也触发，滚动时间缩短（最短为原本的一半、不少于 0.4 秒），弹簧和呼吸也相应减轻（`Roll.dur`、`PWord.rollD`）。
- **漂浮（hover＋圆心）**：镜头整行一起框住（放得进稍微拉远的画面时），每一行比前一行更靠近镜头，唱过的行往后退、变小，不会再比正在唱的行大两倍而冲出画面。
- **特写**：入场时间减半（`enter` 0.12）。
- **结尾的律动**：拍点的摆动以落拍时的音量决定强度，摆动开始后自然跑完；以前整段摆动乘上「现在」的音量，伴奏一弱就被硬拉回。音乐结束后的收束改为 0.8 秒的平滑曲线。

**分词规则层**（`lyrics/rules.ts`）：在最终分词（依唱法合并之后）上逐行套用规则，规则可以把词标为「突出」（`lift`：放大倍数、拉近的纵深）；排版依标记放大并把它放在比同一行前面所有词更近的位置，所以也画在它们上面。新增规则只要在 `WORD_RULES` 加一条。第一条：句尾单独一个汉字（前面有汉字）放大 1.2 倍并拉近。

**纯音乐**：标记为纯音乐的歌，特效歌词里不出现任何歌词文字（也不把歌名当成歌词）；播放页的歌词处固定显示「纯音乐 请欣赏」。

**词怎么切**：分词器（`spacing.ts`：中文 jieba、日文 BudouX、其他 ICU）只给出「可以切的位置」，词从不被切开；真正在哪里切由唱法决定（`phrasing.ts`，在 `buildLyrics` 一开始套用）。逐字时间的歌词：只有歌手停顿的地方才切——下一个词明显比这句的节奏晚到（至少半拍、这句一般字距的 1.8 倍、0.22 秒三者取大），或前一个词有结束时间、停在下一个词之前（至少 0.2 拍、0.12 秒）；其余连着唱的词合成一个。只有整句时间的歌词：看分离出的人声（节奏分析的 `voice`，`rhythm/neural/vocals.ts`：HTDemucs 人声轨与鼓声轨同一轮分离，每秒 50 格、0 无声到 1 这首歌唱得响的程度；没有人声的歌为空）——这句时间内人声低于 0.35 的地方是停顿，短于一口气（0.16 秒或 0.3 拍取大）的不算；字按各段唱的长度分配，每个停顿取最近的分词边界（`voiceCuts`）；一口气唱完的整句合成一个（仍受 6 字上限）。没有人声数据时（没有分离、DSP 引擎、分析未完成），只把单独一个字并到旁边的词。一个词最多 `PHRASE_MAX`（6）个字。只合并中文和日文的词；英文等有空格的词、韩文、标点、和声、紧接着重复的词（滚筒场景用）、用户自己改过断词的句子都不动；句子本身从不合并或拆开。分词编辑页显示的是合并后的结果，存档时和它相同的句子不算手动修改。
