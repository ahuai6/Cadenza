# 引擎（`src/engine`）

Session 管理歌词、风格、节奏图和导演计划。Engine 管理视觉时间、画布和交接，并保留工坊的独立预览传输。桌面流经播放协调器取得输出文件时间。总览在 `docs/ARCHITECTURE.md`。

普通输出播放原生核心解码的 PCM（阶段 1，`src/engine/stream/`）：Worker 读取，AudioWorklet 跨歌连续重采样，`AudioClock.pcmInput()` 接到既有歌曲增益和路由，`heardTime()` 按输出时间戳求出正在听到的位置。工坊继续走 `AudioBufferSourceNode`，可按项目时间独立预览。实时 `Session.audio` 只需时长，有声导出调用 `load()` 明确取得 PCM，视觉重建、逐字歌词及 MV 不占用播放器的数据流。

ALAC 的 PCM 用主进程授权的可 seek WAVE 提供，解码器位于原生程序。Session 无需了解源编码。工坊、导出与分析分别按用途请求 PCM。访问信号、资源上限和格式细节见 [G4R](../G4R.md)。

Hi-Fi 的文件时间经 `hifi-clock.ts` 进入同一个播放传输接口。WASAPI 位置从设备流的单位换算到歌曲时间，同时受提交范围和运行代次约束。播放中允许短时插值，seek 后从新位置开始，设备恢复期间冻结。经典、空间和特效页读取当前播放传输，桌面歌词只消费时间快照及剩余插值预算。歌词偏移、导演计算和 Folia 风格仍在各自的视觉时间域工作。

## 接口

```ts
const session = await Session.open(spec, environment, { signal, analyzeAudio: false })
engine.show(session) // 桌面已通过 followTransport() 绑定协调器，显示场景不会操作音频
```
- **编辑与重建**（`session.ts`）：每个编辑只标记它需要的重建——整个重新规划（`REPLAN`）、从歌词起重建（`BUILD`：歌词、分词、字体、范围、速度）、只重算时间（`RETIME`：歌词微调、片尾长度，不重新解析和分词）、只重算特效触发（`RECUE`：碎玻璃、字形纹样、色散、故障的开关，触发灵敏度、字形纹样频率）。重建同一时间只跑一个（`flush`）；重建期间每帧都会再要求，都并入同一个，期间的新编辑由下一轮处理。旋钮各自读到哪一层见 `KNOB_REBUILD`。
- **规划在背景线程**（2.12，`engine/planner.ts`、`engine/plan.worker.ts`）：重新规划（版面、镜头、触发、标题）在 Worker 里做，画面照旧用目前的规划继续播放，新的规划好了才一次换上。
  - 导演层本来就是纯计算；唯一需要页面的是每个词在这首歌字体下的宽度。页面先把版面可能问到的每个词都量好（`measuresFor`：每个词横排和直排各一份，加上和声；拆字退场时按字量），连同样式一起送过去，Worker 用 `tableMeasurer` 查表排版。单元测试确认查表排出的规划和直接量的完全相同、没有漏量的词，并且经过结构化复制后不变。
  - 节奏图在 Worker 里用同一份分析重建（分析送一次后按键保留最近几份，之后只送键）。
  - 时间、节奏图、歌词模型和规划一起换上（`retime`），不会出现新节奏图配旧规划的画面；流式分析的新结果（`stage`）也在 Worker 里规划。
  - 没有 Worker（单元测试）或 Worker 失败时，同一个规划器在页面上执行。
- **滑块**（`app/ui/kit.tsx`）：`onChange` 在拖动中每一步调用，只放即时预览（只影响画面的部分）；`onCommit` 在放开或键盘步进时调用一次，放需要重建的部分。旋钮拖动时用 `setKnob(k, v, true)` 只更新画面，放开后才重新规划。
- **MV**：MV 是叠在歌曲自己主题上的一层。比歌曲短时，在结束前淡出（`MvSource.endK`），之后画面就是这首歌没有 MV 的样子——主题照它目前的设置，MV 的裁切也解除；预览与导出一致。
- **设置**：各层的设置（`render/gfx.ts` 的画质模式、`rhythm` 的引擎选择／鼓声分离／模型位置、渲染尺寸、MV 外观）都只从 `configure()` 设置。界面在 `app/engineConfig.ts` 把用户设置转成 `EngineConfig`。
- **导出的画质**：每一帧都在 `withGfx('default', …)` 中同步绘制。即时画面保持自己的模式，导出期间改设置也不会被还原。
- **神经网络分析排队**：同一时间只跑一首歌，因为 Worker 中的网络会共用缓冲区。即将播放的歌（`urgent`）优先：
  - 它会插到背景歌曲前面；
  - 若此时正有一首背景歌曲在跑，那次分析会中止，该歌之后再重跑一次，不会退回内置分析。
- **多页面并行渲染**：播放页背景是环境视图，特效视图在后台准备规划与字形。桌面换曲先撤下旧 Session，视觉可保留一份用于过渡的旧画面。即使没有可用的新 Session，输出仍能运行，界面显示新曲目和进度。导出显式等待所选 Session 就绪，工坊继续用自己的预览与导出入口。
- **共享元素过渡**：界面量出 DOM 封面与歌词行的位置交给 `handoff`；引擎从那些位置把封面（旋转角同步、黑胶从封面下滑出）与歌词行飞到场景位置；屏幕特效依过渡进度连续变化。返回时反向。
- **模糊转场不抽搐**：
  - 缩小用逐级减半的平均（`gfx.ts` 的 `downsample`），不是一次缩到很小（一次缩 6 倍以上的双线性采样会产生闪烁的锯齿）；模糊半径换算到缩小后的尺度，下限 1.5 像素，画面上永远看不出低分辨率那一层。
  - 转场前后 0.5 秒内不调整自适应分辨率（分辨率一变，字形缓存也要重建）。
  - 转场峰值之后的第一帧在转场开始前就预热（`lookAhead`），切点后不会因为第一次绘制而卡一下。
- **歌词写入标签**（`electron/library.cjs` 的 `writeTagLyrics`，node-taglib-sharp）：在同一文件夹的隐藏临时副本上写入 MP4 `©lyr`，回读并验证音频负载和其他标签后才替换原件。播放层先释放当前文件的普通媒体资源或等 Hi-Fi 确认关闭文件。同曲目准备等待写入并读取新的文件版本，使用协调器最新的位置和播放意图。TTML 保留原始 XML。非 MP4 的 TTML 保存同名 `.ttml`；非 TTML 格式不支持内嵌时改存 `.lrc`。

## G5.5-B 本地输出交接

关闭 Hi-Fi 的无声问题涉及两个交接缺口。普通 Web Audio 图在原生独占打开前仍连接系统端点，退出时也没有明确的端点归还。原有设置事务只发出异步重播命令就返回，不能确认新输出是否接管。进度更新因此不足以证明音频已恢复。

`PlaybackCoordinator.handoff` 记录有效时间、播放意图和队列实例，撤销旧输出，等后端完成交接，再以同一队列实例准备新后端。进度和 seek 跟随当前代次。普通端点通过 `AudioContext.setSinkId` 停放和恢复，复用 Gain 和空间声场图。不支持停放的环境使用挂起与恢复。退出 Hi-Fi 等待原生进程关闭，再恢复普通图。同曲交接复用已就绪的视觉会话，保持播放历史和队列实例。用户切歌、暂停和 seek 可以在等待期间更新意图。

隔离 Electron 测试使用前后频率不同的合成片段，Rust 模拟设备检查 seek 后的 PCM，普通输出检查图内频谱。真实 Windows 默认端点另测共享和独占。恢复时间以命令到页面观测运行状态为口径，频谱与 PCM 用于单独确认音频内容。真实原生输出的物理端点、蓝牙和外接 DAC 仍需独立测量。

一次 Windows x64 拆包版测试记录如下。每种方式为单次样本，包含运行状态被测试脚本观测的时间，不能推算 P95 或物理发声延迟。

| FLAC 交接 | 普通 → Hi-Fi | Hi-Fi → 普通 | 原生 seek 到 7 秒后的首次观测 |
| --- | ---: | ---: | ---: |
| 真实 WASAPI 共享 | 215.8 ms | 98.4 ms | 7.0166 s |
| 真实 WASAPI 独占 | 479.2 ms | 430.2 ms | 7.0060 s |

两次真实切回均通过普通音频图信号和往回 seek 的频率验收。隔离的原生模拟设备跨四种格式、两种模式验证输出内容，首个 seek 位置观测相对目标约晚 1.8–17.7 ms。

## 切歌时的画面交接（阶段 1）

切歌时 `Engine.clear()` 先拿下当前会话，新会话要等音频就绪后才构建。此前这段时间渲染循环只清空画布，特效歌词黑屏到新场景出现为止。现在旧画面在新会话就绪前保持原样：非专辑保留快照，专辑连播让上一首按自己的时间继续跑；`show()` 到来时才开始原有的 0.9 秒模糊淡出或 3.2 秒延续。新场景 4 秒内仍未就绪（例如构建失败），旧画面照常淡出。`NpLyrics` 在显示的那一次播放换了（按 `Session.showing`：歌曲的键加这次打开的序号，同一首歌再播一次也算新的）时用 `--t-stagger` 和 `--ease` 做一次淡入上浮，同一次播放的重新规划不重播，系统要求减少动态效果时不播放。

**节奏的替换时机**（4.0.0-alpha.8）：Session 已经跟着一份读取（开头延伸或完整读取）时，更好的读取只在下一个模糊转场的高点换上（`SWAP_UNDER`），不论多远；之前最多等 8 秒，之后就在画面上直接叠化。还没有任何读取、歌里已没有转场、特效歌词不在画面上或画面由风格自己的镜头控制时，照旧立即替换（特效歌词在画面上时带叠化）。拖动进度时画面本身就会跳切，替换可能随之发生。
