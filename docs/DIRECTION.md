# 目前的方向

这份写「Cadenza 要变成什么、现在走到哪、接下来做什么、用户已经决定过什么」。接手的人先读这份，再读 `ARCHITECTURE.md` 与开发范式（`.claude/skills/cadenza/SKILL.md`）。版本的细节在 `RELEASE.md`。

3.6.0（`4157fd8`）是对比基准。4.0.0 开发分支在 G0 建立基线，G1 建立资料断代策略，G2 建立播放协调和视觉解耦，G3 将普通输出迁到浏览器渐进式媒体管线，G4 治理 WASAPI 设备事务、流时钟和数字样本精度。后续阶段仍按 G0–G9 路线独立授权和验收。

## 1. 要变成什么

一个安静、成熟、功能完整的本机音乐播放器。它的特色不只一样：好用的音乐库与高保真播放、读懂节奏、完整的歌词支持、随音乐运镜的特效歌词与 Folia 风格、正在播放页、歌词工坊与视频导出、桌面歌词、可以走动的空间界面——每一样都要做到成熟，而且彼此咬合。所有部分都是同一件事的出口——一首歌被听见、被看见、被感觉到节奏：

- 音频输出时间推进播放，节奏提供事件，歌词提供文本和时间戳。播放、渲染与界面各有明确的状态所有权。
- 界面不像工具：技术词不上主画面，高级的东西收在「高级」。
- 两种界面（经典、空间）是同一个播放器的两种走法，功能只定义一次。

## 3. 接下来

重构路线先建立基线，再处理 4.0.0 数据断代、播放、分析与持久化、WebGL2 及书页界面。每个阶段独立授权。其余 Folia 风格继续列入后续积压，现有风格的还原、效果组合和上游更新能力是本轮验收要求。

当前实施平台是 Windows。Android 只预留输出、存储和界面适配边界。实机与模拟数据的区别见 [3.6.0 基线](BASELINE-3.6.0.md)。

### G6 节奏识别引擎与调度验收

1. 对照 Folia 上游核查 Beat This!、HTDemucs、鼓点、重音、律动、置信度和节拍算法的移植完整性。
2. 标清上游原始实现、经过验证的有意改写和历史兼容补丁，清理证实已失去作用的补丁。
3. 统一 DSP、WebGPU、ONNX Runtime 的分析结果、算法版本和失败语义。
4. 移除 Folia 适配层对节拍力度和节奏有效性的重复估算，保留风格特有的视觉响应。
5. 处理完整 PCM 分析、重复解码、后台推理的资源占用和长音频限制，维持 G3 的流式起播与内存收益。
6. 基于 G5 内容身份与缓存协议完善分析结果持久化、任务优先级、取消及 GPU/CPU 预算。
7. 建立识别质量对照，覆盖复杂拍号、半拍与倍速、自由节奏、无鼓段落及鼓点种类。
8. 明确上游版本与模块映射，使随 Folia 更新可以定位并核验差异。G7 接续验证统一节奏数据到 Folia 的视觉接口与画质。

## 4. 用户已经决定的（不要再问、不要改回）

- **严格遵守平台授权与 DRM**：受保护的文件只列出，不解密、不播放；不规避会员限制。
- **不提交**商业歌词、音乐档或用户数据；测试用自己写的假数据。
- **Folia 的颜色**：只接 Cadenza 的自订颜色与封面取色，对应上就好；Folia 自己生成主题色的机制不要。
- **Folia 的搬法**：上游构图代码原样搬入、可以随时跟上游更新；能拆的都拆开，可以交叉搭配；保留 Folia 特殊的分词（可选）与运镜。
- **外观与风格的分类**：外观／风格／高级／特效四个分页；外观和风格任意搭配。
- **正在播放页**：背景可选 Folia 背景；歌词样式不接 Folia 风格（见上）。等待的三点：从中心出现与收回，期间随拍放大点亮，离场提前半拍放大再缩小，曲线像 Apple Music。
- **设计**：方向 B「书页」覆盖经典和空间界面。经典界面的右侧播放底座向左伸展，封面随之一同移到左栏。空间保留展馆和马赛克。专辑默认网格，可切换到节拍线。先实现 Windows，通用布局和交互为不同屏幕与触控预留适配能力。
- **汇报**优先用简体中文；文档用简体中文与大陆惯用词；代码注释英文；提交消息与代码不写模型名称。
- **开发与发布**：4.0.0 开发使用 `refactor/4.0.0`，逐阶段授权并在 Windows 本机验证，完成后只推送同名远端。正式发布需全部阶段完成、本机验收和用户明确批准，再合入 `main`。常规维护及触发规则见 [维护文档](MAINTENANCE.md)。
- **依赖**一律跟最新稳定版、精确锁定（`README.md`）。

## 5. 判断优先级

1. 播放不中断、不走音、不泄漏内存。
2. 画面跟音乐是同一件事：任何动态都要能回答「它跟着音乐的什么在动」。
3. 界面安静、成熟。
4. 代码让下一个人看得懂、接得上。
