# 目前的方向

这份写「Cadenza 要变成什么、现在走到哪、接下来做什么、用户已经决定过什么」。接手的人先读这份，再读 `ARCHITECTURE.md` 与开发范式（`.claude/skills/cadenza/SKILL.md`）。版本的细节在 `RELEASE.md`。

状态：3.5.0（2026-11）。

## 1. 要变成什么

一个安静、成熟、功能完整的本机音乐播放器。它的特色不只一样：好用的音乐库与高保真播放、读懂节奏、完整的歌词支持、随音乐运镜的特效歌词与 Folia 风格、正在播放页、歌词工坊与视频导出、桌面歌词、可以走动的空间界面——每一样都要做到成熟，而且彼此咬合。所有部分都是同一件事的出口——一首歌被听见、被看见、被感觉到节奏：

- 节奏是唯一的时间来源，歌词模型是唯一的文字来源，播放器状态是唯一的「现在在放什么」。
- 界面不像工具：技术词不上主画面，高级的东西收在「高级」。
- 两种界面（经典、空间）是同一个播放器的两种走法，功能只定义一次。

## 3. 接下来

1. **其余的 Folia 风格**（用户指定留到下一轮）。上游 `components/visualizer/` 下还有：cappella、claddagh、classic、diorama、fume、hanabi、lumiere、machi、metaphor、nebbia、partita、pendolo、still、tilt 等。做法和商籁、凝彩相同（`SKILL.md` 第 4 节「新增一个 Folia 风格」）：
   - 先读上游的 runtime，判断它是 Pixi（走 `src/folia/pixi/`）还是 DOM／React（要另写画法）。
   - 能拆的拆开：滤镜、标记、转场、背景、镜头各自登记，让它们能和 Cadenza 的风格交叉搭配。
   - 每做一种都用 `tests/folia-compare.cjs` 对照，数字写进 `FOLIA.md`。
   - **正在播放页的歌词样式**目前不接任何 Folia 风格；之后做到适合放在正在播放页的风格才接（用户的决定）。
2. 空间界面的设置卡改用纲要的剩下部分、`COPY.md` 第 3 节剩下的两项。
3. 实机才能确认的：显卡上的性能、声音、Windows 窗口行为（这个环境只有软件绘图）。

## 4. 用户已经决定的（不要再问、不要改回）

- **严格遵守平台授权与 DRM**：受保护的文件只列出，不解密、不播放；不规避会员限制。
- **不提交**商业歌词、音乐档或用户数据；测试用自己写的假数据。
- **Folia 的颜色**：只接 Cadenza 的自订颜色与封面取色，对应上就好；Folia 自己生成主题色的机制不要。
- **Folia 的搬法**：上游构图代码原样搬入、可以随时跟上游更新；能拆的都拆开，可以交叉搭配；保留 Folia 特殊的分词（可选）与运镜。
- **外观与风格的分类**：外观／风格／高级／特效四个分页；外观和风格任意搭配。
- **正在播放页**：背景可选 Folia 背景；歌词样式不接 Folia 风格（见上）。等待的三点：从中心出现与收回，期间随拍放大点亮，离场提前半拍放大再缩小，曲线像 Apple Music。
- **设计**：主方向「舞台」（A），专辑页用「节线」（C）；「书页」（B，用户也叫它「方案 B」「像普通播放器但更稳的那个」）没有采用，留作参考（`DESIGN.md` 第 9 节）。空间是「抽象展馆」，浅色是傍晚、深色是午夜。
- **汇报**优先用简体中文；文档用简体中文与大陆惯用词；代码注释英文；提交消息与代码不写模型名称。
- **发布**：推 `space-mode` 是预览建置，快转推 `main` 才是正式发布（`MAINTENANCE.md`）。
- **依赖**一律跟最新稳定版、精确锁定（`README.md`）。

## 5. 判断优先级

1. 播放不中断、不走音、不泄漏内存。
2. 画面跟音乐是同一件事：任何动态都要能回答「它跟着音乐的什么在动」。
3. 界面安静、成熟。
4. 代码让下一个人看得懂、接得上。
