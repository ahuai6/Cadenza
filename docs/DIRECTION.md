# 目前的方向

这份写「Cadenza 要变成什么、现在走到哪、接下来做什么、用户已经决定过什么」。接手的人先读这份，再读 `ARCHITECTURE.md` 与开发范式（`.claude/skills/cadenza/SKILL.md`）。版本的细节在 `RELEASE.md`。

3.6.0（`4157fd8`）是对比基准。4.0.0 开发分支在 G0 建立基线，G1 建立资料断代策略，G2 建立播放协调和视觉解耦，G3 将普通输出迁到浏览器渐进式媒体管线，G4 治理 WASAPI 设备事务、流时钟和数字样本精度。G4R 独立复审这些成果，补齐 ALAC 与 MP4 内嵌歌词链路。后续阶段仍按路线独立授权和验收。当前行为以源码、对应测试和 [架构说明](ARCHITECTURE.md) 为准。当期用户要求决定产品目标。下面的历史记录用于解释此前的决策。

## 1. 要变成什么

Cadenza 是以本地音乐为核心的播放器和视觉创作平台。日常状态、编辑模式、独立音乐厅和空间玩法的职责及实施阶段见 [产品架构](PRODUCT.md)。

- 音频输出时间推进播放，节奏提供事件，歌词提供文本和时间戳。播放、渲染与界面各有明确的状态所有权。
- 界面不像工具：技术词不上主画面，高级的东西收在「高级」。
- 编辑模式与界面路由独立，切换时保持播放器、视觉和已打开编辑草稿的生命周期。音乐厅独立于本地页面导航，在线任务使用主进程服务。
- 书页设计继续采用安静的排版。新音乐厅以纯白、浅灰块面及留白为默认基调，尊重已保存的主题。G9 再将块面语言、完整预设及动效统一到全局。

## 3. 接下来

重构路线先建立基线，再处理 4.0.0 数据断代、播放、分析与持久化、WebGL2 及书页界面。每个阶段独立授权。其余 Folia 风格继续列入后续积压，现有风格的还原、效果组合和上游更新能力是本轮验收要求。

当前实施平台是 Windows。Android 只预留输出、存储和界面适配边界。实机与模拟数据的区别见 [3.6.0 基线](BASELINE-3.6.0.md)。

### G5 与 G5.5 音频身份、媒体来源和编辑

G5 分开建模本地条目、实际音频内容、远端平台曲目和资源档位，以及音频、元数据、歌词和算法版本。相同内容可共享分析缓存，条目和用户资料保持独立。证据不足的文件替换挂起关联，应用内可验证的标签编辑保留音频分析。G5.5-B 采用授权明确的适配器接入平台，LyricsFlow 是独立计划来源。G5.5-C 升级现有元数据和歌词工具，AI 翻译使用官方 Sign in with ChatGPT、获授权的 Responses API 或 DeepSeek API。在线接口及分批方案见 [在线系统前置研究](ONLINE-RESEARCH.md)。

文本编辑逐步支持查找、局部或全部替换、选区、撤销重做和统一快捷键。空白行、纯时间戳、分段及多轨保存在原始歌词文档中。整理属于独立操作，需要预览与撤销。逐行歌词不得标为逐字。

### G6 节奏识别引擎与调度验收

1. 对照 Folia 上游核查 Beat This!、HTDemucs、鼓点、重音、律动、置信度和节拍算法的移植完整性。
2. 标清上游原始实现、经过验证的有意改写和历史兼容补丁，清理证实已失去作用的补丁。
3. 统一 DSP、WebGPU、ONNX Runtime 的分析结果、算法版本和失败语义。
4. 移除 Folia 适配层对节拍力度和节奏有效性的重复估算，保留风格特有的视觉响应。
5. 处理完整 PCM 分析、重复解码、后台推理的资源占用和长音频限制，维持 G3 的流式起播与内存收益。
6. 基于 G5 内容身份与缓存协议完善分析结果持久化、任务优先级、取消及 GPU/CPU 预算。
7. 建立识别质量对照，覆盖复杂拍号、半拍与倍速、自由节奏、无鼓段落及鼓点种类。
8. 明确上游版本与模块映射，使随 Folia 更新可以定位并核验差异。G7 接续验证统一节奏数据到 Folia 的视觉接口与画质。

### G7 风格构图与共享 GPU 基础设施

Cadenza 原生与 Folia 各个风格各自拥有构图、镜头、转场及特效规则，可共享时钟、节奏数据、GPU 资源、缓存和合成接口。检查疾走、滚筒通过 Cadenza 导演对 Folia 造成的间接影响，核实突发运镜、转场跳过、复杂画面掉帧及 Canvas 2D 与 WebGL2 混合开销。交叉组合需要明确能力声明、图层位置和不兼容原因，并按影响范围失效配色及风格资源。保留上游版本映射、自动同步与原始效果对照。允许深入改良 Folia 算法，验证后的改良直接成为该风格的实现，无用户可见版本开关。登记机制须允许加入新风格。

### G8 工坊、预览与导出

三条路径共享视觉配置、渲染能力和音乐时间语义。实时预览消费输出时钟，导出使用确定性帧时钟。用相同项目和时点对照画面、字幕与音频，尤其验证跨来源组合和导出音画同步。

### G9 书页设计、完整预设与可替换布局

保留方向 B，建立包括外观、风格、背景、字体、配色和特效的协调默认预设，同时支持独立组合和保存用户预设。特效歌词默认比例调整为 16:10，梳理设置覆盖页的有效区域和上下边距，验证配色与设置即改即生效及局部资源更新。布局和导航从稳定状态与命令构建。历史四分页方案只记录当时的菜单组织，后续界面按实际任务和空间重新设计。

## 4. 继续生效的产品和工程边界

- **严格遵守平台授权与 DRM**：受保护的文件只列出，不解密、不播放；不规避会员限制。
- **不提交**商业歌词、音乐档或用户数据；测试用自己写的假数据。
- **正在播放页**保留当前可用的 Folia 背景与歌词展示。待唱点保留节奏响应，按 G7/G9 的视觉与布局契约验证。
- **设计**：方向 B「书页」覆盖经典和空间界面。经典界面的右侧播放底座向左伸展，封面随之一同移到左栏。空间保留展馆和马赛克。专辑默认网格，可切换到节拍线。先实现 Windows，通用布局和交互为不同屏幕与触控预留适配能力。
- **汇报**优先用简体中文；文档用简体中文与大陆惯用词；代码注释英文；提交消息与代码不写模型名称。
- **开发与发布**：4.0.0 开发使用 `refactor/4.0.0`，逐阶段授权并在 Windows 本机验证，完成后只推送同名远端。正式发布需全部阶段完成、本机验收和用户明确批准，再合入 `main`。常规维护及触发规则见 [维护文档](MAINTENANCE.md)。
- **依赖**精确锁定。升级核对 Windows、Electron、授权和行为差异，避免仅因出现更新而替换已有实现。

## 5. 判断优先级

1. 播放不中断、不走音、不泄漏内存。
2. 画面跟音乐是同一件事：任何动态都要能回答「它跟着音乐的什么在动」。
3. 界面安静、成熟。
4. 代码让下一个人看得懂、接得上。
