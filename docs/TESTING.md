## 阶段 2 曲库与数据（`4.0.0-alpha.7`）

- `tests/unit/library-store.test.ts`：曲库索引的快照与日志。只追加标记过的条目，重开后读回；删除的条目随日志删除；崩溃截断的半行被丢弃并重写干净的日志；日志超过快照时合并且不重复回放；正常关闭后的 `db.json` 能被旧的读取器原样打开；没有改动时不写任何文件。
- `tests/unit/library-patch.test.ts`：页面按补丁更新曲库。变化的歌曲原地替换，新的接在末尾，离开的移除，没变的保持同一个对象；按 id 查歌和共用的曲库索引。
- `node tests/library-data-desktop.cjs`：早期构建留在 localStorage 的外观、我的风格、工坊项目、收听选择和队列只搬一次，旧副本保留，之后改过的项目不会被旧副本覆盖；非编辑模式下外观的写入被拒绝；计一次播放、加一首收藏后强行结束整个进程树，重开时两者都在；正常关闭后日志为空、`db.json` 完整。运行时打开 `CADENZA_STORE_CHECK`，每次保存后把磁盘上的索引读回来与内存比较。
- `node tests/library-stress.cjs`：一万首合成歌曲（`CADENZA_STRESS_SONGS` 可改）从空资料扫描。分三段测量：扫描、扫描后 30 秒内（歌曲身份仍在逐首计算）、重开。记录主进程事件循环的最长停顿、页面长任务、更新次数、各进程内存峰值、一次播放计数显示出来的时间，并核对页面上的曲库与主进程一致、歌曲列表只绘制可见附近的行、滚到底能看到最后一首、「显示正在播放的歌曲」能找到未绘制的行。`CADENZA_STRESS_CHECK=1` 另做磁盘读回校验（会拖慢主进程，只用于正确性），`CADENZA_STRESS_ASSERT=1` 断言预算。
- `node tests/continuity-desktop.cjs` 新增连续切歌：120 毫秒内连切五首，逐帧检查画布不留空白（alpha.6.1 报出 130 个空白帧）。

- `tests/unit/pcm-stream.test.ts` 从源码文本加载 AudioWorklet 处理器：同采样率逐位拷贝并在下一个采样接续、44.1 kHz 串联在 48 kHz 输出下接缝残差与曲中相当、预缓冲与断流报告、6 ms 暂停包络、曲尾淡出、定位时先淡出旧流、采样率不同的串联歌自行开始。
- `node tests/gapless-desktop.cjs` 把一段连续正弦在非块边界切成两首（48 kHz WAV、44.1 kHz FLAC、带编码器延迟的 AAC），按专辑连播：普通输出录增益之后的信号，Hi-Fi 读模拟设备的转储。检查正弦递推残差、静音段、接缝前后的相位错位（AAC 两半各自编码，边缘带编解码误差，只要求不多不少一个采样）、无缓冲状态和时钟连续。输出采样率随系统默认设备变化，两种重采样方向都应覆盖。
- `node tests/continuity-desktop.cjs` 打开特效歌词切到下一首（普通与专辑两种），逐帧检查引擎画布在新场景就绪前不留空白，并检查歌词列表的入场动效。换回旧引擎时它报出 21 个空白帧。之后跳转到 12 秒、用「上一首」回到开头，要求画面时钟从新位置继续走（alpha.6 停在目标位置，alpha.6.1 修复）。
- `node tests/streaming-desktop.cjs` 按新管线改写：各格式经图内频谱、损坏文件报错、长曲解码器被卡住时时钟冻结（`stall-decoder-file=` 限定文件）、末尾定位且时钟在定位后继续走、停止与快速切歌后 `--play-pcm` 进程全部退出、文件被改后拒绝播放。
- 原生：`cargo test`（含 `mp4gapless` 的编辑列表与 `iTunSMPB` 解析），`node tests/hifi.cjs`，`node --test tests/hifi-clock.cjs` 与 `tests/audio-identity.cjs`。`tests/desktop-hifi.cjs` 的夹具脚本需要 Python 的 NumPy 与 Pillow。

## G4 WASAPI 输出与时钟

- Windows 使用 `cargo test --locked --manifest-path native/cadenza-audio/Cargo.toml`，再构建同一源码的 Release 程序。用 `CADENZA_NATIVE_TEST_BIN` 指向该程序运行 `node --test tests/hifi-clock.cjs`。验证时钟单位、采样率变更后的恢复位置、时钟重置回退、解码下溢、设备重开、独占失败或成功启动后停滞时转共享、指定端点重新出现、过期配置后的旧请求和单次 EOF。可设 `CADENZA_HIFI_SOAK_SECONDS=45`，验证受控的 1.02 倍设备消费率及帧映射。
- 数字样本从模拟设备输入截取。16 位转 24-in-32、24 位 packed 与 24-in-32、32 位整数路径逐样本比较，包括正负边界和低有效位。另测重采样、声道改变、软件增益、静音、硬件音量偏移和淡变。设备格式的有效位与容器位分别记录。只有匹配源采样率与声道布局、整数精度足够、独占、软件增益为 1 且无淡变的合格区间才标记为精确。报告的精确区间限于向 WASAPI 提交的样本。
- 在隔离构建中运行 `node tests/hifi.cjs`、`node tests/playback-desktop.cjs` 和 `node tests/desktop-hifi.cjs`。用普通 Web Audio 图和模拟端点样本分别验证视觉阻塞期间已经输出。模拟子进程退出后允许重启，旧播放运行不会重新取得授权。版本启动测试覆盖 `alpha.3 → alpha.4` 清理一次和重复启动保留资料。
- `node tests/hifi-wasapi.cjs --real` 会在当前 Windows 默认端点输出低电平合成信号，检查共享与独占协商、时钟来源、暂停、跳转、EOF 和释放。运行前选择合适的本机输出。探针不变更系统音频设置。若有额外端点和环回采集，另测默认设备切换、占用、USB 重连、长时间不同采样率以及音频脉冲和歌词时间的偏差。
- `node tests/baseline/hifi-session.cjs <G3 原生程序> <G4 原生程序>` 在同一机器比较模拟设备运行报告、释放确认及 10 秒暂停期间的原生进程 CPU 和句柄。沿用 `tests/baseline/playback.cjs` 记录实际模拟设备 PCM 和 Web Audio 图信号。运行报告、PCM 到达测试探针和物理端点发声各有不同测量定义。

Windows 本机通过类型和格式检查、393 项单元及架构断言、6 项 Rust 单测、12 项 G4 模拟专项与单独的 45 秒长播、32 项原有原生模拟、19 项 Hi-Fi 桌面及 3 组两路播放生命周期和进程崩溃场景。经典桌面 76 项、空间界面 28 项、资料生命周期及范围协议 17 项通过。普通流式专项的 11 组格式、45 分钟文件的渐进读取与断供恢复、六声道和实际 Electron 空间声场均通过。快切验收检查当前输出后端，另外直接向原生程序提交 64 次准备请求验证最后一次仍可起播。设备切换测试样本来自合成资料，普通与模拟 Hi-Fi 的图内观测分别记录。

实机验证了 Senary Audio 扬声器和随后成为默认输出的 AirPods 蓝牙端点。两者的 48 kHz Float32 共享流都曾取得 WASAPI 流时钟和一次 `IAudioClock2` 设备帧观测。蓝牙共享复测也观测到启动后时钟仍停留在 0 的情况，自动采用 Padding。两路 44.1 kHz 32 位整数与 48 kHz 16 位整数独占流成功运行，启动期间的流时钟观测与提交位置不一致，消费估计转为 Padding。各路均完成暂停、跳转、消费至 2.65 秒并释放。共享的 `GetStreamLatency` 返回 0，两路独占约 9.8 和 20 ms，数值仅作为驱动诊断。本机结果不覆盖 DAC 输出波形、数字回环、受控设备拔插、独占争用或长时间物理漂移。

蓝牙独占曾出现启动确认成功后长期不消费已提交帧。新增消费停滞检测后，两次真实共享及独占复跑完成。停滞后的旧流释放、独占转共享、保留歌曲位置与单次 EOF 由故障注入复现。

## 渲染测试的性能门槛（3.5.0 重新校准）

这个环境的浏览器以软件绘图，比显卡慢数倍，而且快慢随机器而变：以毫秒为门槛时，同一份代码在慢的机器上就会失败。所以 `perf` 先量一段**不含 Cadenza 代码的固定画布工作**（渐层、带阴影的文字、缩放复制、读回一个像素）当这台机器的速度，再把每帧的时间换成它的倍数：

- 3.5.0 量到的倍数（三次在 5% 内）：liquid 9.4、gothic 12.5、cover 11。
- 超过基准 25% 才失败。基准要更新时，在 `tests/render.cjs` 的 `BASE` 改数字并写明版本与原因。

性能结论只能来自实机；这里的数字只看「有没有变慢」。

## Folia 对照

参考页（`tests/folia-ref/`）在 Folia 的 checkout 里建置，用真正的 Pixi 8 与 Folia 自己的 React 背景；Cadenza 这边用 harness（`npx vite build --mode harness`）。参考页需要的套件照 Folia 的 lockfile 版本另外装进 checkout 的 `node_modules`（在 checkout 里直接 `npm install` 会被它的 git 依赖挡住）。

```
node tests/folia-stage-compare.cjs <checkout> <输出>                                # 舞台：文字、图形、模糊、滤镜、遮罩
node tests/folia-compare.cjs <checkout> <输出> sonnet,tempera 0.5                    # 全曲逐格（静止）
node tests/folia-compare.cjs <checkout> <输出> sonnet-beat,tempera-beat 2.1          # 播放中、拍点特效打开
node tests/folia-bg-compare.cjs <checkout> <输出>                                   # 五种背景（静止）＋动态（几何图形、莫奈漂移）
```

做法与注意：

- 两边的 `Math.random` 换成同一个固定种子（Folia 有几处细节用真乱数）。每格在全新状态下画。
- **拍点对照**：两边装同一份合成拍点清单，在虚拟时钟（`performance.now` 被换掉）上以每秒 60 步走过时间点前 1.5 秒，再画那一格。
- **动态背景对照**：Folia 的几何图形与莫奈漂移是浏览器动画，暂停后设到同一时刻（`BG.seek`）；几何图形的版面由同一个种子产生（`BG.seed`）。参考页用 1920×1080：Cadenza 把 Folia 的 CSS 像素当成 1080p 页面的大小。
- 软件 WebGL 偶尔掉格，脚本会重画；磁盘配额用完时浏览器会直接崩溃，先清空间。

3.5.0 的结果（平均色差，越小越像）：

| 对照 | 结果 |
| --- | --- |
| 五种背景（静止） | 0.00%–0.14% |
| 通用背景的几何图形（1、7、13.5、29、61 秒） | 0.02% |
| 莫奈的漂移（6、17、40 秒） | 0.25%（0.5 秒时 0.44%，是淡入） |
| 商籁，静止／播放中 | 粗略重合率 95%／95%；拍点反应两边逐格一致（开关拍点造成的变化两边完全相同） |
| 凝彩，静止／播放中 | 粗略重合率 98%／99%；剩下的差异来自 Folia 在播放状态另以墙钟时间驱动的色块动画，不是拍点 |
