## 上游与版本

- **QQ 音乐** 使用 Denza-Fork 当时采用的 [sansenjian QQ Music API](https://github.com/sansenjian/qq-music-api)。截至 2026-11-26 npm 最新为 `2.6.0`，本轮精确锁定。主进程仅懒加载 `/services` 的榜单操作，限定响应、超时及重定向。未启动 Koa 服务。 npm 12 发出该库的 npm 11 引擎警告，Windows Electron 的 Node 运行探测通过。SDK 与同一搜索端点的复测结果见上表。
- **网易云音乐** 参考 [Enhanced SDK](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced) 的 `4.41.1`，和 Denza 历史引用一致。npm 包未压缩约 15 MB，包含 Web 服务、代理与换源组件。当前保留主进程独立请求模块，对本轮使用的歌词和歌曲权限字段增加适配。生产构建不引入整套工具。
- **酷狗音乐** [MakcRe/KuGouMusicApi](https://github.com/MakcRe/KuGouMusicApi) 历史采用 `v1.6.3`，本轮核实同名最新稳定标签 `5d6c9f7b180279c9dd08bc6f7159de52a856d587`，分支 HEAD 为 `786fe07514b99158d19b24f7f5cea11977a1db67`，日期 2026-11-24。现有公开搜索继续验证，尚未选入 SDK 或复制源码。
- **Apple Music** 官方接口按 [Apple Music API](https://developer.apple.com/documentation/applemusicapi) 的 v1 目录契约。通过 Cadenza 自己的 Apple Music 开发者配置取得令牌，以 `CADENZA_APPLE_DEVELOPER_TOKEN` 注入主进程后重启。在歌曲搜索结果确认目录来源，再尝试试听。实际 MusicKit 用户授权需要正式开发配置。
- **LyricsFlow** 对照 [服务 OpenAPI](https://api.trylyricsflow.com/openapi.json) 2.0.0。清单追踪当前使用的目录、榜单、推荐、关系与歌词字段，另通过 Windows 公网探测补足 OpenAPI 对分页和真实内容的说明。文件服务自报格式或访问成功无法证明保存权限。
- **歌词** 原始 Apple Music TTML 与网易云 YRC 直接读取，不清洗空行或时间戳。Denza 的 QRC 解包引用 [LRC-GET](https://github.com/valenbine/LRC-GET) `2cc0e67d`，未引入该快照及转换流程。Denza 的 KRC 翻译及解析来源为上述酷狗项目，当前未接入。

Denza-Fork `custom` 当前仍为 `7152ca59236ec7f753a7562e4ddeded7d0dcf39a`。本轮核对了平台适配器、下载租约、标签校验和依赖来源，继续把它作为研究参考。 [Denza 接口说明](https://github.com/ahuai6/Denza-Fork/blob/7152ca5923/docs/DENZA-ONLINE-API.md)

## 可复核的更新流程

1. `npm run online:upstream` 读取 npm 最新版、酷狗 HEAD 和公开 OpenAPI。协议版本或必要参数不符合时退出失败。检查过程不改工作区和锁文件。
2. SDK 更新先在开发分支精确安装候选版本，审查许可、运行时依赖和敏感请求边界。按对应适配器和实际已采用版本更新清单。生产包仍从锁文件安装。
3. `npm run online:verify` 检查依赖定义和锁文件一致，并运行可重复的在线契约用例。`npm run build:app` 会先执行这项离线检查。随后跑 Windows 公网和打包回归。候选失败时撤回候选依赖、锁文件与对应适配变更。远端协议变化单独修复和验证，不因 OpenAPI 自报版本自动升级。
4. 签入更新时记录实测账号、公开能力和模拟验证的边界。注意公网测试会依赖当时服务状况，普通离线回归无此依赖。

## 下载与歌词

主进程先检查操作的访问类型。公开能力不要求本地账号，私有能力按当前会话授权。保存还必须通过媒体租约与资源校验。下载沿用暂存、精确编码校验、内容身份、排他落地和增量入库。公开下载权限边界有隔离用例，暂无新增公网可保存来源。

FLAC 原文、译文和音译可写入音乐文件的独立 Vorbis Comment。字段通过同一次重写校验，保留音频和其他块。译文或音译已存在且不同，保留现有字段并沿用附属来源。其他容器的辅助轨仍明确作为同目录来源；TTML 原文不转写成 LRC。从系统目录选择器选过的目录可与音质一起保存为默认配置。单次可改用其他目录，已完成任务可以在资源管理器中显示原文件。仍未实现跨容器辅助轨内嵌选择、批量入库、主播放器内定位和不定长下载。

## 本机复核方法

- 无账号时打开 Apple Music，选择实际 Storefront，搜索一个已知曲目或粘贴官方歌曲地址。回退结果应标出 LyricsFlow。点击可用的短试听，关闭音乐厅后检查主播放器恢复到原曲及停止位置。
- 使用 Cadenza 自有的 Apple Music 开发者令牌重新启动，重复同一目录查询。官方返回应使用官方目录。阻断官方网络可复核可恢复失败仍能使用公共回退。当前构建的账号页能显示缺少配置，尚无 MusicKit 用户账号登录入口。
- 在网易云账号页使用自己有权操作的账号扫码并确认。先同步个人歌单，确认完整曲目和顺序，再选可合法保存的曲目。核对可选音质、真实格式、保存位置和曲库新增记录。再次打开音乐厅或重启后，可确认默认目录与音质。下载许可失败应停止任务。
- QQ 的榜单有独立验证入口。当前若搜索报上游错误可从榜单进入官方页面，复核 SDK 接口变化时跑 `npm run online:upstream` 和公网测试。酷狗当前的可实测入口是公开搜索。

## 本轮 Windows 记录

- TypeScript、42 个 Vitest 文件共 396 项及 6 项在线契约均通过。公网拆包回归取得网易云、酷狗、Apple Music 回退歌曲各 25 条，QQ SDK 榜单 25 条。QQ 搜索报上游错误且显示正确失败状态。
- 公网 Apple Music 短试听取得 Web Audio 信号，关闭窗口后恢复原曲。经典及空间模式 640 像素窄窗均可纵向滚动，无横向溢出，账号页和主题检查通过。
- 拆包版真实 WASAPI 默认端点各执行一次 FLAC 双向交接。共享接管和切回分别为 238.9 ms、119.5 ms，独占为 458.7 ms、493.3 ms。数值是操作到测试探针观察到运行状态的时间，单次样本不用于计算分位数或 DAC 延迟。模拟设备另验证四种格式和双向 seek 后的信号内容。
- 使用合成媒体测试下载失败和重试、拒绝试听租约、冲突分支、精确音频身份、文件可播放及原词和译文标签。新建空白资料后扫描同一目录，从 FLAC 本身读回两个字段。长时间资源与真实账号文件验收仍未完成。
