# G7 二维 GPU 渲染与风格世界

基线为 `0082539d541e63f70f953f7285942b5aed00a13d`。测试使用独立资料目录与合成音频。开发版号和资料代次延用 G6。

## 实现与选择

| 问题 | 本轮实现 |
| --- | --- |
| 原生歌词和 Folia 滤镜分别拥有 WebGL 设备。Folia 最终输出还要复制到一块中间 Canvas | `core/webgl.ts` 统一二维设备和上下文代次。原生字形、装饰光点、Folia 静态文本、精灵和简单色块走同一实例化路径。滤镜、网格、图集复用同一上下文。能完整在 GPU 绘制的滤镜输入直接进入帧缓冲，最后一次直接写合成目标 |
| 滤镜实例和分辨率变化反复分配纹理。纹理上传和纹理容量原来都记在同一个统计里 | `GlRunner` 分开输入、交换缓冲、附属纹理及 Shader。普通滤镜复用按 64 设备像素分档的容量，同时保持原逻辑大小与取样范围。读取下层画面的滤镜保持严格匹配的输入尺寸。有效窗口不受纹理预分配大小影响 |
| 旧 GPU 对象在 WebGL 上下文恢复后继续使用。切歌和切风格时也可能留下旧舞台 | 丢失事件阻止默认永久丢失，当下可以绘制的部分退到 Canvas2D。恢复代次改变后重建纹理、程序、VAO 和帧缓冲。旧计划在完成过渡或被替换后销毁风格实例。舞台位图按 RGBA 字节计费，离开舞台后主动释放位图与临时画布 |
| Folia 文字用自己的 Shot，却叠加原生导演的背景变换、部分闪光与预热 | `render/engines.ts` 登记视觉世界。画面使用 Folia 的镜头或原生镜头其中之一。Folia 的公共字幕读原歌词文档的时间，原生字幕继续跟随原生编排。公共背景保留自身的动效，公共屏幕效果和明确支持的前景仍可组合 |
| 相同歌曲的位置因实际绘制频率、回拉进度或大小变化出现不同的节拍包络 | Folia 节奏包络按媒体时间回读近 1 秒事件，沿用上游衰减与强度曲线。凝彩的景深变化以参数修改时的媒体时间为锚点。更改渲染密度保持舞台和动画位置，几何尺寸变化仍按需排版。保留上游各风格自己的 Shot 和转场时长 |
| 外观、运动和单曲设置来自不同历史入口 | 个人完整预设存为 `VisualPreset` v1，包含风格、导演参数、字体、背景、配色、图层和效果。旧平铺预设可读，应用个人完整预设保留歌曲或项目的画布和抗锯齿设置。可继续使用局部外观和运动选择。特效歌词与新建工坊使用 16:10，明确保存的比例优先 |

保留项目的 Pixi 兼容舞台，在明确可加速的绘制上实测迁移。整套替换成 PixiJS 会同时重做原生歌词的字形/SDF 与遮罩语义，并触及工坊和输出的生命周期。Pixi v8 继续作为上游对照执行器。当前仍有 CPU 排版、字体回退、字形栅格化、复杂路径、部分遮罩与混合，以及最终 Canvas2D 合成。Three.js 管理自己的空间三维上下文，既有 Paper 背景也保留独立执行器。共享设备覆盖二维歌词与舞台的主要 GPU 资源，完整画面尚未迁移到单一帧缓冲图。 [PixiJS Renderer 文档](https://pixijs.com/8.x/guides/components/renderers) · [WebGL 资源实践](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)

渲染层按背景、世界后景、歌词世界、世界前景、公共前景、屏幕空间执行。`effectSupported` 以坐标及图层依赖为准。普通背景可和 Folia 组合，羽毛、碎玻璃碎片和哥特锁链可进入公共前景。特效面板禁用只适用于原生构图的选项，切回原生风格仍能恢复用户选择。配色不会重新对原封面取色，歌词或字体变化重新布局，换封面刷新封面相关背景，节奏更新通过现有 Session 挂入。原生相机计划保留供现有入口使用，Folia 运行时不采用其中的镜头、转场时刻或字形预热。设置面板使用标题栏之下的覆盖区域，打开面板不改变媒体画布与导出坐标。

## G6 修缮

自动模式继续通过音频内容身份、分析配置、算法版本和已有原子写入保存结果。缓存索引额外记实际质量，区分 DSP、只有神经拍点、已完成鼓轨判断三种情况。可用能力提高后后台排队补全。同一内容和能力档位失败后最多每 24 小时重试一次，新的能力档位可立即尝试。旧结果可用于播放，更低质量的迟到结果无法覆盖更高质量行。共享音频条目仍共用同一份分析。

Beat This! 完成后在分轨前发出检查点。HTDemucs 失败或超时可保留拍点。显式神经模式拒绝用 DSP 拍点冒充成功，保留 `failed`、`skipped` 和 `drumless` 的含义。Folia 读取神经重音、独立的 trackScale 和 DSP 的已发布事件。没有节拍证据时不造拍，缺失频段时不以响度伪造各频段。格式适配结果随 `RhythmMap` 修订在内存复用，切换或淡入淡出不重新提取全曲特征。

## 上游与保真

同步仍从 `6ee9404f` 生成 124 个文件。阶段调查时上游主分支为 `d88a6f056bc8bf90cd5c1292e5006c61f72c1e8f`，近期变化涉及其他风格，当前基准下继续使用已对照的商籁和凝彩。绝对时间挂钩由同步清单记录。自动分词与用户选定的歌词分词继续走既有入口，同一输入时间测试用上游 Pixi 页面输出作对照。 [Folia 上游](https://github.com/chthollyphile/folia-major)

同歌词、字体、1280×720 与 0.25、8.25、16.25、24.25、32.25 秒截图中，商籁轮廓 IoU 82.4%、粗略轮廓 92.2%、平均 RGB 差 0.66%。凝彩分别为 93.2%、93.9%、4.19%。以 24.25 秒的相似度较低，因此保留该转场时间点供后续回归。商籁的导线、故障错位和凝彩的色块仍有清晰的视觉区分。舞台对照新增批量色块模糊案例，修正从图集白色纹素取样时的边缘透明度，最终 IoU 99.1%，亮度总量比 0.99，RGB 差 0.02%。该案例按轮廓和亮度比例做自动断言。其他场景留存对照截图及分数，巨型细描边仍对像素栅格化敏感。

## Windows 测量方法

`tests/g7-render.cjs` 在固定 Electron 45.1.0 和 RTX 3070 Ti Laptop GPU（ANGLE D3D11）上重播同一确定性测试段。每种风格与尺寸预热后统计 85 次提交，保留窗口截图与 JSON，GPU 查询只含 WebGL pass，浏览器帧间隔另计。纹理上传字节是根据 RGBA 尺寸估算的源数据量，容量分配及 Windows 显存工作集分别记录。

```powershell
npx vite build --mode harness
node tests/g7-render.cjs dist-harness <结果目录> --verify --pressure
node tests/folia-stage-compare.cjs <构建了参考页的上游 checkout> <结果目录>
$env:CADENZA_NEURAL_HARDWARE='1'
$env:BUILD='0'
node tests/neural.cjs
```

先对 G6 的 harness 产物按同样流程采样，再交换候选的 harness 目录。用 `CADENZA_TEST_EXE` 指定相同的解包 Electron EXE，渲染探针通过本机 HTTP 载入 harness。用正式界面回归检查真实的播放、导出和窗口行为。Spector.js 独立在凝彩的 1920×1080 帧中捕获 186 条命令、9 次 draw、6 次 clear、5 个程序且无 WebGL 错误。捕获工具的时间读数未用于性能表。

1920×1080 凝彩的活跃 WebGL 上下文计时 P50 为 2.74 → 4.97 ms，P95 为 9.14 → 10.18 ms。探针记录到 361 → 919 次 GL draw，原先在 Canvas 执行的绘制也计入新值。GPU 接手更多绘制时，应用提交中位数缩短，最长帧仍需治理。商籁上传量明显降低，帧间隔和提交速率在本轮较差，不能以减少上传推断整帧已经变快。

两轮各 480 帧压力测试切换风格、画布尺寸及渲染密度。二维上下文由 2 个降至 1 个，Windows 归到 Electron GPU 进程的专用显存由 513 → 962 → 925 MiB 改为 485 → 676 → 700 MiB。Renderer 私有内存由 468 → 597 → 582 MiB 改为 484 → 569 → 567 MiB。两轮分别约 26 秒。这组值包含 Electron 和驱动的工作集，不能据此判定多小时无泄漏；G7 第二轮显存仍略增。强制丢失 WebGL 上下文后可以绘制回退帧，恢复代次后重新提交且无 WebGL 错误。

实际硬件 WebGPU 合成曲测试报告 `nvidia ampere f16`。Beat This! 的 46 秒合成曲模型段约 1.64 秒，应用分析调用 2.17 秒，节拍误差约 16.2 ms。短片段的 Beat This! 约 145 ms，HTDemucs 模型约 3.57 秒，找到 35 个击打。无鼓前奏未被判定为有律动。`CADENZA_NEURAL_STEM_FAULT=1` 阻塞 HTDemucs 模型读取，验证在 5 秒超时后仍保留 22 个真实模型拍点，不误报为无鼓。900 秒原生 PCM 流式测试验证尾部拍点、重复文件复用、清理过程中取消及再次建立缓存。复合拍号和不同编曲的真实音乐采样与跨设备质量基准仍需扩充。

## 播放与交付边界

类型检查及 45 个测试文件的 407 项测试通过。Windows 曲库测试验证 DSP 仍可读取、不同模型能力分别退避、神经拍点部分成果可升级，且迟到的 DSP 写入无法降级同一内容。播放桌面回归在原生、商籁和凝彩之间往返，确认普通输出的 Web Audio 频率信号及模拟 Hi-Fi 当前运行保持。合成 FLAC 在真实 Windows 共享及独占模式验证双向输出交接。模拟输出另覆盖 MP3、AAC 和 ALAC。ALAC 专项验证逐样本解码、范围读取、进度跳转、工坊有声导出和标签写入。未测物理 DAC 端点。

用 Electron 45.1.0 在 Windows 本机构建 NSIS 安装包 `Cadenza-Setup-4.0.0-alpha.4.exe`，SHA-256 为 `95a9259aa94ae3f7d86a169587b512067fb1de2f94e6fe6e9520f91654c40f09`。构建未签名。最终解包版以隔离资料通过 77 项桌面断言，覆盖特效歌词、按风格禁用特效、MV 进出与片尾、工坊和 1152×720 有声 MP4。最终包亦复跑实际 Windows 共享与独占交接，原生侧分别约 302 和 764 ms 报告接管，恢复到普通输出的 Web Audio 信号分别约 102 和 111 ms。是单次接管数据，未测物理 DAC 延迟。

4K、高 DPI 的全组合、多小时实际硬件运行、完整的 Folia 视频时序对照及更丰富的真实音乐未完成本轮验证。商籁的近景文字工作集、复杂遮罩和极长帧仍是后续性能检查点。离线渲染已可按媒体时间与给定尺寸提交帧，工坊、预览和导出的完整生命周期由 G8 接续。
