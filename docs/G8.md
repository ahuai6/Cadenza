# G8 音乐响应、GPU 合成与创作执行

对照基准是 `8293302a82ec66a2525d561f9c9570896b312706`。以下实测使用独立应用资料和合成素材，曲库吞吐另用具有开放授权的钢琴录音。未纳入真实个人曲库。

## 音乐分析

未分析曲目开播时，普通输出从既有 Web Audio 图读取频段和能量。Hi-Fi 用带运行代次的原生 PCM 能量观测，等输出消费位置进入相应帧区间时随位置报告。Folia 和 Cadenza 在媒体时钟有效时读取这些信号。实时信号没有确认节拍时只驱动能量响应。

G6 流式解码和分析线程继续负责读取 PCM。G8 分阶段交付已经测得的频谱、响度和可信神经拍点，每个部分都有明确覆盖范围。未覆盖区间按即时能量显示，跳转不会延长已有分析窗口。完整结果通过既有 G5 文件修订、内容身份和提交令牌验证后原子持久化。临时结果不写入完整缓存。

自动模式先计算可复用的基础 DSP，再按模型和运行时能力补拍点与鼓轨。排序使用基础分析、独立响度、质量升级三个等级。暂停后台、观看特效歌词和导出的限制仍经统一调度，观看期间继续基础分析并推迟新启动的自动质量补全。当前曲目可以取消不相关的活动任务。解码线程与一次模型请求可在有界窗口内重叠，最终仍按媒体时间合并。显式神经模式继续遵循用户选择。下载缺失、安装部分模型、驱动不可用与实际推理失败独立呈现，下载先限量暂存、校验模型再提交。

真实曲库使用 26 首 CC0 Goldberg 钢琴录音，共 4,130 秒。G7 的默认自动模式已完成首曲原生解码却在前 130 秒内尚无完整结果，大部分时间出现在反复调用 HTDemucs 的分块。G8 自动模式首次基础结果在 18.08 秒出现，125.30 秒覆盖 26 首，随后才开始首个神经升级。重启后，26 条仍有完整基础结果且观测窗内零原生解码。独立 DSP 实测 90.11 秒覆盖全部 26 首，仅神经拍点的一次观察窗在 65.18 秒内已有 7 首。测试在本机 NVIDIA WebGPU 下分别运行，G8 自动模式与图形压力任务重叠，不能将这些计时解释为受控的倍率对比。该曲库适合观察长曲、弱鼓和密集钢琴音，完整神经加分离吞吐和更多曲风仍需另测。 [素材来源](https://archive.org/details/The_Open_Goldberg_Variations-11823) · [Web Audio 观测接口](https://developer.mozilla.org/en-US/docs/Web/API/AnalyserNode)

Windows 打包版 900 秒合成曲目测试中，普通输出图内首个信号为 626–628 ms，约 1.75–2.16 秒测得视觉已消费实测输入和首段频谱。模拟 Hi-Fi PCM 首个信号为 447 ms，2.99 秒测得视觉响应。后三个视觉时间观测均发生在完整分析之前。900 秒末段分析、重启缓存复用及取消重建均通过。

## GPU 合成

继续使用 G7 的共享 WebGL2 设备。Folia 的独立绘制批次按变换后的影响区域合成，屏幕外的文字在栅格前裁掉，保留抗锯齿边界。常用滤镜之间的中间结果保留在 GPU，路径及少数特殊混合仍按需走 Canvas2D。大画布压力解除后，长期过大的 GPU 表面可以回缩。资源复用边界仍随实际布局、字形、像素比例和主题修订变化。

同一 Windows Electron、RTX 3070 Ti Laptop、ANGLE D3D11，三轮交替 G7/G8。每组 85 帧，以各轮统计的中位数列下表。画布和视觉参数一致。帧间隔包含调度和浏览器合成，WebGL query 单独统计。上传量根据实际调用及源尺寸估算，不等同显存。

| 场景 | 指标 | G7 | G8 |
| --- | --- | ---: | ---: |
| 商籁 1080p | 探针 FPS | 70.8 | 73.4 |
| 商籁 1080p | 帧间隔 P99，ms | 116.6 | 95.9 |
| 商籁 1080p | 85 帧上传，MB | 451.0 | 276.2 |
| 凝彩 1080p | 帧间隔 P95，ms | 25.1 | 25.0 |
| 凝彩 1080p | 帧间隔 P99，ms | 50.0 | 54.2 |
| 原生流体 720p | 帧间隔 P99，ms | 100.1 | 87.5 |

商籁上传量差异稳定，帧时间分布仍有交叠。三轮对照在最后一次图集尺寸调整前完成。最终代码另跑一轮相同场景，商籁 1080p 的 85 帧估算上传从 459.1 MB 降至 332.3 MB，帧间隔 P99 为 87.6 → 87.5 ms，P95 为 29.3 → 33.4 ms。并发压力下，图集调整后的单轮 P99 曾到 125.1 ms。凝彩的连续滤镜仍产生较多中间操作，当前三轮未显示长帧改善。主动丢失 WebGL 上下文后，探针恢复绘制且 GL 错误为零。Spector.js 在浏览器场景的单帧中捕获了 42 条 WebGL2 命令、2 次绘制及 2 次清除，没有 GL 错误。硬件计时仍来自独立 Electron 探针。

单轮 3840×2400 实测定位到商籁大字纹理频繁逐出。此前只要任一边超过 1100 像素，就分配独立纹理。按有衬距的图集容量及面积重新分类后，细长文字图可共享图集。变体的 85 帧估算上传由约 5.27 GB 降至 1.14 GB，帧间隔 P95 由 325.0 ms 降至 108.3 ms。两轮与其它压力并发，仅作专项验证。商籁同一分辨率仍可观察到 366.7 ms 的 P99 长帧。

30 分钟 Electron 硬件压力探针记录 60 组、共 28,800 帧，风格切换、分辨率调整与时间跳转中保持一个 WebGL2 上下文。采样点的渲染进程私有内存为 585.3–710.5 MiB，末次 651.0 MiB。WDDM 报告 GPU 进程专用显存为 623.2–771.2 MiB，末次处在该区间上沿。这是图集尺寸策略最后调整前的重复渲染探针，结果表明存在数百 MiB 的运行工作集。尚不足以判定无泄漏，也不替代音乐、模型与最终 EXE 同时运行的长测。

## Folia 原生场景

上游锁定 `6ee9404f`。核对上游 `d88a6f05`，这两个版本之间商籁、凝彩及节拍核心目录无改动。同步清单管理本地修改，并用 `scripts/folia-sync.mjs --check` 对照 124 个文件。商籁继续编译上游的编辑列、重击字、碎片拼贴、跟踪带、遮罩揭示、海报块、静态构图七类 Shot，使用快模糊、单色故障、镜头拉动等上游转场。凝彩继续运行自身的歌词构图、间奏桥段、前后景与重叠转场。Cadenza 仍有自己的歌词分词、字体、公共背景、节拍和配色输入，这些需要在完整产品对照时逐项控制。

每个 Folia 世界独立维护节拍状态。商籁撕裂按媒体时间推进，视觉装饰种子绑定歌曲与段落。已获得离线频段时，可从有限信号历史重建平滑状态。样式或分析参数变化时，只有输入和种子都相同才沿用同一个舞台，避免旧布局和参数残留。

用锁定的 Folia 源码和真实 Pixi v8 运行时对照 16.00–23.75 秒的连续 32 个绝对时间采样，报告保留逐帧 Shot、镜头值、转场、图像和重合数据。两款风格的 Shot 在各自 32 个采样点全部一致。商籁窗口覆盖重击字和遮罩揭示，像素区域 IoU 为 79.8%，粗粒度 IoU 为 92.7%，平均 RGB 差 0.82%。凝彩窗口覆盖交叉、双带、指针三类构图，相应为 94.5%、95.5% 与 2.44%。该对照使用软件 WebGL，范围包含选定的切换片段。全曲、复杂多声部和真实音乐下的视觉一致性仍要独立观察。 [Folia 上游](https://github.com/chthollyphile/folia-major)

## 视觉执行、工坊和导出

播放、工坊及视频使用同一种 `RenderFrame` 和风格世界。播放以音频时钟为准，工坊保持自身时钟，导出固定每帧媒体时间并使用独立 Engine、视觉实例及参数快照。工坊的 v2 项目可以存储曲库条目及音频内容身份，加载时核对当前内容修订。旧项目可继续打开视觉数据，失联音频按视觉项目处理。G5 身份和 G6 完整分析缓存继续复用。

导出采用独立视频素材元素，长本地 MV 可按区间取帧。视频、音频编码队列设背压，释放 WebCodecs 帧及编码器。标准 48 kHz、样本对齐的单声道和立体声使用每次最多 4,800 帧的 PCM 编码输入，去除第二份全长离线 PCM；其它采样率、亚样本偏移和多声道沿用 Web Audio 转换。取消通知可中止媒体准备的 Fetch。Chromium 已提交的整曲解码仍要等待完成。Windows 文件 IPC 由窗口所有者管理，用同目录暂存、同步并在封装成功后提交。取消和失败会删除暂存，既有文件保留到有效的提交点。新目标用无覆盖提交，当前依赖文件系统支持硬链接。没有文件系统权限时界面回报失败。音频输入仍要完整解码，超长作品尚未达到全链路的有界内存验收。

打包版导出回归真实写入 HEVC + AAC 文件。`ffprobe` 读得 1152×720，16:10，30 FPS，1,305 帧，视频 43.500 秒、AAC 流 43.520 秒，两轨从零开始。FFmpeg 完整解码成功。对比去掉第二份全长 PCM 前后同一素材的 AAC 解码样本，37 秒前和 40.5 秒后逐样本一致，37–40.5 秒尾部包含淡出差异，RMS 差约 −85.9 dBFS。该素材不用于声学校准。独立 Chromium 导出商籁 3840×2160、16:9、60 FPS、180 帧 H.264 无声作品，3 秒成品耗时约 207 秒。这个浏览器压力结果只验证可编码及帧时间，不能作为 Electron 硬件导出吞吐。

## 验证范围

包和桌面回归沿用 `4.0.0-alpha.4` 及现有数据代次，未为了本阶段主动断代。测试及其观测层级见 [测试说明](TESTING.md#g8-分析场景和创作验证)。图内信号、模拟设备 PCM 和真实 WASAPI 流时钟是不同观测；无物理 DAC 回环的结果不用于断言绝对出声时间。环境没有独立覆盖所有驱动、模型组合和真实硬件场景。

已运行 TypeScript、48 个 Vitest 文件共 413 项、7 个 Windows Rust 测试、124 个 Folia 同步检查及 Windows NSIS 构建。Electron 专项覆盖隔离经典和空间窗口、ALAC 普通与模拟 Hi-Fi、实际 WASAPI 共享与独占交接、资料身份及分析缓存。浏览器导出测试涵盖 PCM 读取取消、现有预览状态保持、输出抽帧和画质独立。新建本地 NSIS 包未签名，未运行正式安装或发布。

G8 仍有工程限制。跳到尚未分析的区间可以消费实时能量，后台的长曲解码还没有优先重排到跳转点。整库神经加分离的完成时间、最终产物与真实音频并行的长时资源曲线、商籁高分辨率长帧、凝彩滤镜中间资源，以及更多原生场景的全曲动态对照尚未闭环。
