# 審計報告（2.9.2）

範圍：自訂元素與介面背後的接口和參數；特效、背景、粒子的圖層邏輯；鏡頭、歌詞類型和兩個場景是否生效；邏輯錯誤與調參卡頓。只檢查、沒有改程式碼。

## 一、介面與參數：沒有功能、不生效、不對版

| # | 項目 | 狀況 | 嚴重度 |
|---|---|---|---|
| A1 | 特效「色散」「故障」開關 | 觸發時機在規劃時算好，但切換這兩個開關不會重新規劃。剛打開時不會觸發，要等改了別的設定才生效；關掉後舊的觸發時間也還留著 | 高（實際不生效） |
| A2 | 旋鈕「漂浮感」 | 字本身的漂浮會立即改變，但鏡頭的手持漂浮和擺動寫在規劃裡，這個旋鈕不會重新規劃，所以那部分不更新 | 中（只生效一半） |
| A3 | 旋鈕「進場時長」 | 入場速度立即改變，但字提前出現的時間和規劃好的入場位移要等下次重新規劃才更新 | 中（只生效一半） |
| A4 | 旋鈕「運鏡速度」 | 它同時調整的「漂移幅度」沒有任何程式讀取（鏡頭的漂移速度是寫死的），預設裡的 drift 數值也都沒用 | 低（部分失效） |
| A5 | 殘留項目 | 已移除功能的「轉向區間」（`m.flip`、重新規劃表裡的 `flip`）、介面文字 `m.*` 一整組、舊主題名稱（炫酷、電子、溫柔、霧光、墨白、切割、平滑）都沒有使用 | 低（清理） |
| A6 | 重新規劃的分級 | 旋鈕表標了「只需重算鏡頭」「只需重算觸發」等不同等級，但實際上任何需要重算的旋鈕都整個重新規劃（排版＋鏡頭＋觸發），浪費時間 | 中（效能） |
| A7 | 特效自己的參數 | 光點數量、字環數量與樣式、字形紋樣對比、反色幾何入場：都有被讀取 | 正常 |
| A8 | 全域設定 | 各設定項都有對應的程式使用 | 正常 |
| A9 | 背景專屬特效 | 碎玻璃、門框、背景線條、立體線條、碎塊在任何背景下都會畫，不是只有哥特、唱片才有效 | 需修正方案：風格系統方案原本打算「只在對應背景顯示」，這會拿掉其實能用的選項，改為分組標示即可 |

## 二、圖層邏輯

目前每一幀的繪製順序：

| 順序 | 內容 | 跟隨鏡頭的方式 |
|---|---|---|
| 1 | 背景，以及背景層特效（光點、羽毛、節拍光環、網格、頻譜、唱片系列、碎玻璃板、字形紋樣） | 鏡頭的旋轉和縮放，加上一半的平移視差 |
| 2 | 閃光（整片疊色） | 固定在畫面上 |
| 3 | 帷幕開啟時的底色 | 固定 |
| 4 | 歌詞後方：歌詞框線、字環 | 跟著字的投影 |
| 5 | 歌詞（含動態殘影） | 投影，依遠近受力 |
| 6 | 歌詞前方：星星 | 投影 |
| 7 | 前景：哥特鎖鏈、幾何前景、碎玻璃碎片、前景羽毛 | 各自處理，多數跟著畫面晃動 |
| 8 | 反色閃光 | 固定 |
| 9 | 模糊轉場 | 固定 |
| 10 | 閒置點、字幕、開場、片尾卡、結尾淡出到背景色 | 固定 |
| 11 | 帷幕 | 固定，不受震動影響 |
| 12 | 螢幕特效：顆粒、暗角、掃描線、色散、故障、反色幾何 | 固定，蓋在所有東西上，包括帷幕 |

整體順序合理，也符合之前的要求（帷幕在螢幕特效之下、不受震動）。不一致的地方：

| # | 問題 | 建議 |
|---|---|---|
| B1 | 背景層特效跟隨鏡頭的方式不一致：背景、封面、地面、粒子、唱片系列會跟著平移視差；節拍光環和碎玻璃板只跟旋轉縮放，不跟平移 | 統一由背景層一次套用視差，各特效不自己處理 |
| B2 | 「反色幾何」放在螢幕層，會連字幕、片尾卡、帷幕一起反色 | 移到前景層（字幕之前）；或確認這是刻意的 |
| B3 | 結尾淡出到背景色之後才畫螢幕特效，所以畫面全黑後顆粒、掃描線、暗角還在 | 若要「完全結束」，螢幕特效也跟著淡出 |
| B4 | 粒子類分散在三層：光點在背景層，羽毛分背景和前景兩層，星星在歌詞前方；這是設計，但沒有文件說明 | 在架構文件裡列一張「特效 → 圖層 → 跟隨方式」表；風格系統的特效分組照這張表 |
| B5 | 依遠近受力只作用在歌詞世界（歌詞、星星、框線、字環），背景層是統一的一半視差 | 合理，維持 |

## 三、預設、鏡頭與兩個場景是否生效

用測試歌詞，在 6 種鏡頭 × 3 種歌詞類型下各規劃一次：

| 項目 | 結果 |
|---|---|
| 俐落：每次抵達的頓挫 | 有（約 80～100 次） |
| 圓舞：彈簧踢動 | 有（約 55 次） |
| 特寫：較多快速模糊轉場 | 有（10～11 次，是其他鏡頭的兩倍） |
| 懸停：停在詞組中間 | 有 |
| 置中：三列一組、每組轉場 | 有 |
| 滑行：往左的行用懸停取景 | 有 |
| 圓心：不排豎排 | 有 |
| 疾走場景 | **有效**：快而密的歌詞 10 句中有 9 句觸發，所有鏡頭都會（置中除外，這是設計） |
| 滾筒場景 | **有效**：重複的詞會滾動；但兩次重複之間的時間不夠完成一次滾動（約 1.5 秒）時就不滾，所以唱得很快的重複不會轉，看起來像「沒觸發」 |
| 歌詞框線 | 特寫鏡頭下自動框線關閉（設計如此），`$1` 手動框線仍會畫 |

近幾次修改沒有讓任何鏡頭或場景失去觸發。兩個需要注意的地方：

- **沒有疾走場景的測試**：之前沒有任何測試檢查疾走場景，以後改動可能悄悄弄壞它，應補上。
- **滾筒的時間門檻**：快速重複不滾動是刻意的，但如果你希望快速重複也有效果，可以改成「時間不夠就滾小一點、快一點」。

## 四、邏輯錯誤與調參卡頓

### D1：調參時每動一下就整個重新規劃（確認，就是你懷疑的問題）

- 滑桿每一次數值變化都會立即套用，不是放開滑鼠後才算。
- 會重新規劃的旋鈕（運鏡速度、力度、轉向幅度、空間縱深、字號、觸發靈敏度、字形紋樣頻率）以及多數下拉選單，每動一下就在主執行緒上整個重新規劃一次。這期間畫面和介面都停住。
- 實測一次重新規劃的時間（測試歌詞 48 句）：

| 鏡頭 | 一次重新規劃 |
|---|---|
| 特寫 | 1.30 秒 |
| 俐落 | 0.90 秒 |
| 滑行 | 0.64 秒 |
| 圓舞 | 0.52 秒 |
| 懸停 | 0.27 秒 |
| 置中 | 0.06 秒 |

- 拖一下滑桿通常會產生十幾個數值變化，所以會卡好幾秒。
- 每次重新規劃後，還會重新烘焙字形快取，整個面板也會重新繪製。
- 2.7 加入「鏡頭自己加的轉場帶回排版重排，最多三輪」之後，規劃時間比以前長。

### D2：歌詞微調和片尾長度滑桿會同時跑好幾十次完整重建（嚴重）

- 這兩個滑桿每動一下就從頭重建：重新解析歌詞、分詞、等字體、重新規劃。
- 重建時會等字體載入（最多 1.2 秒）。等待期間，每一幀都會再啟動一次新的重建，沒有「已經在重建就不要再開」的保護，所以拖動時會同時堆起幾十個重建。
- 換字體、套用預設、編輯無歌詞歌曲的資訊也走同一條路，只是不是連續觸發，影響較小。

### D3：拖動顏色時

每一步都會產生新顏色的大字點陣圖。快取有上限，不會無限增長，但拖動期間會比較吃力。

### 修正方向

| 問題 | 做法 |
|---|---|
| D1 | 只影響畫面的參數（光暈、律動、漂浮的字本身、入場速度、殘影、顏色）拖動時即時預覽；需要重新規劃的參數放開滑鼠後才重算，拖動期間只更新數字 |
| D1、A6 | 依旋鈕實際影響的範圍只重算需要的部分，例如運鏡速度只重算鏡頭 |
| D1 | 長期：規劃移到背景執行緒，不擋畫面；並縮短多輪重排的時間 |
| D2 | 同一時間只跑一次重建，新的變更合併到下一次；歌詞微調只需重新規劃，不必重新解析和分詞 |
| A1–A3 | 讓色散、故障開關和漂浮感、進場時長這兩個旋鈕觸發它們需要的重算 |
