# 舊專案（詞幕 Lyric Motion 2.1）架構審計

本文件記錄 Cadenza 重構前對舊專案的全面審計：先讀完全部程式碼（engine 3,200 行、shell 2,600 行、electron 640 行、Rust 1,600 行），再對使用者回報的每個現象找出**經驗證的根本原因**，最後歸納成共同的架構缺陷。重構的每一項決定都對應到這裡的某一條。

標記：✅ 以程式實測證實；🔍 以程式碼閱讀確認（有明確的程式路徑）。

---

## 一、共同根源（先說結論）

| # | 根源 | 影響的現象 |
|---|------|-----------|
| R1 | **全域可變狀態**：引擎 12 個檔案共用同一個全域作用域（`STYLE`、`t`、`W/H`、`lines`、`shots`、`AUD`…約 60 個全域變數），任何函式都能讀寫任何狀態。導出時甚至暫時改寫 `W/H` 再重建鏡頭。 | 無法有兩個引擎實例；工坊與播放器只能「輪流」佔用同一引擎（`stage.js` 每次切換都整個重載）；任何新功能都要碰底層 |
| R2 | **多個各自計時的時鐘**：引擎 `t`（音訊時鐘）、播放頁背景（`performance.now()`，30fps 自己的 rAF）、播放頁歌詞彈簧（自己的 rAF）、MV 淡入（`performance.now()`）、轉場動畫（WAAPI），彼此沒有共同時間基準。 | 兩個介面背景節奏不同步、切換時狀態不同步、背景過期 |
| R3 | **同一個視覺概念有兩套實作**：播放頁背景（`backdrop.jsx`）與「封面」主題背景（`drawCoverBG`）各畫各的、各自載入封面、各自算調色盤。封面、歌詞在 DOM 與 canvas 也各有一份。 | 過渡只能「模擬」，元素無法真正銜接；切歌後背景過期兩秒 |
| R4 | **節奏資訊被各模組重複推算**：只有「每拍一個」的拍點網格（`trackBeats`），每拍附帶幾個特徵；之後 `accentAt`、`soundingAt`、`ringBeats`、`strongAt`、`KICKS`、`beatStrength`、`buildAt`、`IMPACTS`、`flashShots` 各自用不同的閾值與窗口重新判斷「這裡算不算重」。 | 節奏粒度粗（一拍內不能有多個不同強度的事件）；各效果對同一拍的反應不一致；無法替換演算法 |
| R5 | **「先規劃、再層層補丁」的鏡頭管線**：滑行路徑 → `leanAhead` 預傾 → 縮放包絡 → 高斯平滑 → 安全框修正（兩輪）→ 單向進度修正。每一層都在修改上一層的結果，而不是把約束放進規劃本身。 | 鏡頭「懸而不決」、反覆修正；歌詞框打開後鏡頭劣化；硬朗切換向右拉扯 |
| R6 | **同一個量在多條程式路徑各算一次**：例如未唱字虛影、入場描邊、正式字形各自計算位置；DOM 與 canvas 各算一次封面位置。 | 虛影與落點偏差（入場抖動）；過渡落點對不準 |
| R7 | **命令式動畫編排**：WAAPI 動畫互相 `cancel()`，狀態散落在 React state、DOM dataset 與動畫物件三處，沒有單一狀態機。 | 迷你播放器展開「卡住」在半途 |
| R8 | **全域 CSS 命名空間**：不同元件共用類名。 | 播放列表行錯位、資料被擠壓 |

## 二、逐項現象 → 根本原因

### 渲染

**1a. 兩句歌詞重疊並伴隨晃動時閃爍** ✅
`drawWorld` 每幀以 `dd`（深度）排序所有字再依序繪製；`dd` 包含 `ry*cam.tx + rx*cam.ty`，也就是「手持漂浮」的假傾斜，每幀都在變。重疊的兩個字深度接近時，繪製順序在相鄰幀間來回交換。半透明字、光暈與色散在交換順序後疊出不同的顏色 → 閃爍。
實測（60fps 逐幀，`long.lrc`）：liquid 主題每首 138 次、gothic 80 次、punch 142 次重疊字對換順序。
→ 修正方向：繪製順序由規劃階段決定的**穩定鍵**（層/行/字序）決定，不隨視角變化。

**1b. 歌詞部分出界時，連未出界的部分也一起消失** ✅
不是剔除（cull）造成的：把剔除判斷整段移除重繪 308 幀×5 個主題，像素完全相同。
真正原因在 `project()`：假傾斜把深度寫成與畫面位置**線性**相關（`dd = d + ry*tx + rx*ty`），離畫面中心越遠的字，深度變化越大，透視係數 `kp = F/(F+dd)` 隨之暴增，並撞上 `-F*0.55` 的夾值。實測畫面邊緣的字最大被放大 **2.9 倍**、被甩出 **1.9 萬像素**，每首歌數百次撞到夾值。所以鏡頭一移動、句子一部分出界，剩下的部分就被透視「甩」出畫面。
→ 修正方向：真正的相機模型（旋轉後的視平面 + 有界的傾角），投影只依相機姿態，與字在畫面上的位置無非線性耦合；剔除以完整變換後的包圍盒計算。

**1c. 未唱歌詞虛影與實際落點有偏差，入場像抖一下** 🔍
同一個字的位置在三處各算一次：
- 虛影（未唱）：`translate(u.cx+ux, u.cy+uy)`，**含**漂浮偏移 `uy += sin(...)*FL*2.6`；
- 入場描邊（剛唱）：`translate(u.cx, u.cy)`，**不含**漂浮偏移；
- 正式字形：含漂浮偏移與入場位移。

字從「未唱」變成「已唱」的那一幀，描邊從含漂浮的位置跳到不含漂浮的位置 → 抖一下。
→ 修正方向：每個字只有一個「靜止位置」函式，虛影、描邊、正式字形、光暈、陰影都從它派生。

**1d. 全屏模糊轉場不夠從容** 🔍
轉場進入/離開時長被夾在 0.2–0.45 秒（`clamp(...,0.2,0.45)`），且只對齊「最晚的拍或半拍」，沒有考慮反拍弱起（下一句從弱起拍開始時，峰值應落在弱起拍上）。
→ 修正方向：轉場時長以拍為單位（約 1–1.5 拍進、1 拍出），提前開始；峰值對齊下一段真正的起點（含弱起）。

**1e. 重拍時鏡頭「擰動」像抖動** 🔍
`KICKS` 用 `lobe(u,0.16)` 做 7° 滾轉，`IMPACTS` 用 `lobe(u,0.035)`：35 毫秒就升到峰值的單次擺動，再加上 2° 滾轉與位移。這是位移衝擊，不是彈性系統。
→ 修正方向：統一的二階阻尼彈簧（低音喇叭紙盆：快速推出、帶一次微小回彈的衰減），以縮放為主，滾轉為輔，由節奏 SDK 的事件強度驅動。

**1f. 阿拉伯數字（短間隔逐字時間）卡頓** 🔍
`<00:25.570>１ <00:25.600>２ <00:25.630>３<00:25.660>`：每個數字後有空格，被拆成**三個詞**，相距 30 毫秒。每個詞各產生一個鏡頭移動（punch 模式下是三次獨立的硬切移動）、各自的入場模糊與新的模糊字形快取。60 毫秒內三次鏡頭啟動、三批模糊字形同時生成。
→ 修正方向：歌詞模型在規劃前做**時間正規化**：低於感知融合門檻（約 90–120 ms）的連續單位合併成一個運鏡/入場群組，入場依音樂最短時值錯開。

**1g. 打開「歌詞框」後鏡頭劣化** 🔍
歌詞框是在排版**之後**才決定的（`planFrames` 在 `layout` 之後），所以排版沒為框留空間；鏡頭事後把該字的縮放改成框的縮放並把位置往框中心拉 70%，安全框再把框的外框當成「要在畫面內的字」加進去修正。結果：起始可能在畫面外，事後修正變多，被迫長距離拉回而不是轉場。
→ 修正方向：框在排版**之前**決定，框的外輪廓就是那組字的佔位；鏡頭規劃直接以它取景。

**1h. 鏡頭「懸而不決」** 🔍
見 R5：路徑建好後還要經過 5 道修正，每道都會在局部推回或拉前一點。

**1i. 硬朗切換持續鎖中心卻向右拉扯** 🔍
`leanAhead` 對所有鏡頭風格都會把每個停點往下一個字的方向推（閱讀方向大多向右），而硬切模式又在每個字上重新置中取景 → 每個字都先置中、再被推向右。
→ 修正方向：三種鏡頭風格是三種**策略**，共用規劃器；構圖不鎖死中心，沿演唱方向緩慢前移；超出最遠位移閾值改用模糊轉場。

**1j. 「字紋」解析度低** 🔍
字紋是一張 720 px 的點陣圖，被放大到 1300 px 以上繪製；三層描邊。
→ 修正方向：每幀直接以向量描邊繪製，兩層、提高對比。

### 節奏

**2a. 識別粒度粗** 🔍
`trackBeats` 只輸出「每拍一個」的位置；重拍判斷只在拍點上做（加上「拍前八分音符」一種弱起例外）。一拍內的多次重擊（雙踩、切分重音）無法表示；強度只有一個連續分數，各模組自己切閾值。
→ 修正方向：獨立的節奏 SDK，輸出**事件流**（任意時間、分層強度：重/中重/輕、頻帶類型、節拍位置、是否切分），以及拍、小節、樂句、段落、能量曲線；所有視覺模組只讀它。

### 播放介面與過渡

**3a. 播放頁 → 特效歌詞的過渡是兩個獨立畫面的模擬** 🔍
DOM 封面複製成一張 canvas（ghost）飛過去，同時特效頁以遮罩擴散露出，最後 ghost 淡出到引擎畫的封面上。兩個畫面各自計時（WAAPI 與引擎時鐘），封面旋轉角度、黑膠、螢幕特效、歌詞都沒有真正銜接。
→ 修正方向：引擎同時就是播放頁的背景；過渡時封面與歌詞由引擎接手繪製（從 DOM 量到的位置飛到場景位置），螢幕特效以同一個過渡進度連續變化。

**3b. 播放頁歌詞「成片上浮」而非逐字** 🔍
DOM 歌詞每行一個彈簧；逐字只改了填色漸層 `--p`，沒有逐字的位移。

**3c. 返回播放頁時背景過期兩秒再硬切** 🔍
見 R3：播放頁背景在特效頁期間停止繪製（`live && !fx`），回來後重新載入封面圖、重算調色盤才更新。

**3d. 特效頁切歌沒有過渡** 🔍
`loadTrack` 直接取代全部狀態（暫停、重設 `t=0`、重建）。

**3e. 沒有前奏標題** 🔍 功能不存在。

### 介面

**4a. 迷你播放器展開偶爾卡住（截圖 1）** 🔍
見 R7：`openPage`/`closePage` 用 `getAnimations().cancel()` 互相取消；`closePage` 的 `finished.then(end)` 在被取消時永不執行，`data-vis`、卡片 `data-flying` 與 React 的 `np` 狀態就此不一致，封面停在飛行途中。
→ 修正方向：一個轉場控制器，所有部件由**同一個進度值**驅動的彈簧，任何時刻都可反向，狀態不可能分裂。

**4b. 播放列表模式字樣換行、行未對齊、資料被擠壓（截圖 2）** ✅
`.qrow` 這個類名同時被播放列表行和「編輯歌曲資訊」的標籤搜尋結果使用；後者帶 `display:grid !important; grid-template-columns:1.2fr 1fr 1fr auto` 覆蓋了播放列表行的欄位定義。模式按鈕以 4 等分格線擠在面板內，「結束後暫停」換行。
→ 修正方向：元件樣式各自作用域（CSS Modules 式命名），控制項以內容寬度排版。

**4c. 進度條白色小顆粒（截圖 3）** 🔍
填充條用 `transform: scaleX(k)` 縮放一個圓角矩形：圓角端點被一起壓扁，GPU 以全寬柵格化再縮小，端點抗鋸齒變成零星亮點。
→ 修正方向：以 `clip-path: inset(... round)` 裁切，不縮放幾何。

**4d. 特效頁隱藏游標後移動滑鼠無法重新顯示** ✅
游標顯示與「底部控制列是否顯示」綁在一起（`.fx[data-bottom=false][data-right=false]{cursor:none}`），而底部列只在滑鼠靠近底部時才顯示 → 在畫面中間移動永遠不顯示游標。
→ 修正方向：游標有自己的閒置計時：任何移動立即顯示，靜止 2.5 秒後隱藏。

**4e. 播放頁沒有播放列表按鈕** 🔍 只放在迷你播放卡上。

**4f. 圓形元素過多、圓角不協調** 🔍 圓角各元件各寫各的數值；複選框、懸停陰影是圓形。

## 三、重構原則（由以上根源推出）

1. **沒有全域狀態**：引擎是可實例化的類別；工坊與播放器各有自己的實例/工作階段。
2. **一個時間基準**：每幀只有一個 `FrameContext`（時間、節拍取樣、相機、調色盤、過渡進度），所有圖層、效果、DOM 同步都從它讀。
3. **規劃與求值分離**：歌曲載入後由「導演」一次規劃出不可變的 `ScenePlan`（排版、鏡頭路徑、效果事件、轉場、標題），播放時只做純函式求值 `evaluate(plan, t)`。約束（安全框、距離閾值、歌詞框）在規劃時解決，不事後修補。
4. **節奏只識別一次**：節奏 SDK 產出事件流與結構，衍生訊號（脈衝、彈簧）也由 SDK 統一提供。
5. **每個量只算一次**：字的靜止位置、封面位置等都只有一個函式，所有派生繪製都由它來。
6. **效果是外掛**：效果宣告自己的圖層、參數結構、規劃與繪製；主題只是「效果清單 + 參數」；介面依參數結構自動產生控制項。
7. **介面動畫只有一個進度值**：轉場由狀態機 + 可反向的彈簧驅動。
