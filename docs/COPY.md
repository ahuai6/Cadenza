# Cadenza 文案與命名

介面上出現的每一個字都從這裡來。這份文件有三個部分：寫法、詞彙表、目前已知要改的地方。

狀態：**初稿**。詞彙表記錄的是 3.0.5 介面上實際在用的詞，加上已經確定的取捨。標成「待定」的項目會在第 3 階段（新設計語言）連同整個介面一起定案，定案前不要自己挑一個用。

## 1. 寫法

**說使用者得到什麼，不說程式做了什麼。**
「播放時不卡頓」是使用者得到的；「預先繪製字形與轉場」是程式做的。標題用前者，後者最多放在說明裡，而且只在「進階」出現。

**一個東西一個名字。**
同一個東西在選單、按鈕、提示、設定頁、說明文字裡用同一個詞。要換詞就全部一起換，並且先改這份表。

**按鈕寫動作，動作寫結果。**
按鈕是動詞開頭（「加入歌單」），做完的提示說發生了什麼（「已加入『雨天』」），兩邊用同一個詞。

**不用需求描述裡的臨時名稱。**
討論功能時隨口叫的名字（「空間模式」「極客感」「小窗」）不是產品用詞。一個新東西要上介面，先在這裡取名。

**專業內容放在專業的地方。**
演算法名稱、模型名稱、技術參數只出現在「進階」與診斷資訊裡。一般設定頁看不到「神經網路」「快取」「幀」這類字。

**語氣。**
平實、簡短、不賣弄。不用驚嘆號，不用「哦」「啦」「～」，不擬人，不道歉連發。錯誤訊息說三件事：發生了什麼、資料有沒有受影響、現在可以做什麼。

**標點與格式。**
中文用全形標點；中文與英數字之間空一格（「匯出 MP4」）。「…」用一個字元，只加在按下去還會再問一次的動作後面（「匯出影片…」）。

**各語言各自寫。**
其他語言不是逐字翻譯：先確定這句話要讓人知道什麼，再用那個語言自然的說法寫。英文用英式拼寫（favourite、colour）。

### 空間介面的房間

房間的名字只是地點，不帶宗教或建築術語。程式碼裡的識別字：`gallery`（長廊）、`atrium`（中庭）、`lists`（收藏室）、`listening`（聆聽室）、`settings`（工作室）（3.2.1 起，取代舊的 `nave`、`dome`、`altar`）。

| 用詞 | 英文 | 放什麼 |
| --- | --- | --- |
| 長廊 | Gallery | 專輯 |
| 中庭 | Atrium | 全部歌曲 |
| 收藏室 | Collection room | 歌單 |
| 聆聽室 | Listening room | 正在播放的歌 |
| 工作室 | Studio | 設定 |

空間裡的物件：**收音機**（Radio）——中庭水池邊那台可以拿起來的音源；動作是「拿起來」「放下」。

## 3. 已知要改的地方

已處理（3.1.2）：

- 「重新掃描」只指重新讀取資料夾；重新讀一首歌的節奏叫「重新讀取節奏」，提示也用同一個詞。
- 動作是「加入收藏／取消收藏」，那張清單是「收藏」。
- 「播放清單」統一為「歌單」，「歌曲庫」統一為「音樂庫」。
- 設定裡的技術詞改成說結果的名字（3.1.3）：節奏識別→讀取節奏、引擎→讀取方式（精確／快速）、分析時機→新歌何時開始、預先繪製→先準備接下來的畫面、畫質模式→畫面效果（完整／省力／最省力）、清除所有快取→清除暫存資料。

- 空間介面的字串併進主字典（`sp.` 開頭的鍵），`ts()` 只是讀它們的簡寫；空間設定卡的欄位改由設定綱要產生（3.1.4）。
- 「清除所有資料」的說明不再出現「快取」（3.1.4）。

還沒處理：

1. **說明文字太長**：效能與除錯類（用顯示卡繪製歌詞、顯示效能數據、詳細除錯日誌）的說明還是實作細節。
2. 主字典與 `sp.` 之間仍有意思相同的詞（例如 `sp.q.mid` 與 `sp.line.mid`），重建空間時一起整理。


## 4. 怎麼加一個新詞

1. 先查詞彙表：這個東西是不是已經有名字。
2. 沒有的話，在這份文件加一列（用詞、英文、指什麼、不用哪些說法），再寫進字典。
3. 動作的名字寫在指令裡（`src/app/commands/`），設定的名字跟著設定綱要（`src/app/settings/schema.ts`）；選單、按鈕、提示都從那裡取，不在畫面元件裡另外寫字。
