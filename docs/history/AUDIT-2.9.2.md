# 审计报告（2.9.2）

范围：自订元素与介面背后的接口和参数；特效、背景、粒子的图层逻辑；镜头、歌词类型和两个场景是否生效；逻辑错误与调参卡顿。只检查、没有改程式码。

## 一、介面与参数：没有功能、不生效、不对版

| # | 项目 | 状况 | 严重度 |
|---|---|---|---|
| A1 | 特效「色散」「故障」开关 | 触发时机在规划时算好，但切换这两个开关不会重新规划。刚打开时不会触发，要等改了别的设定才生效；关掉后旧的触发时间也还留着 | 高（实际不生效） |
| A2 | 旋钮「漂浮感」 | 字本身的漂浮会立即改变，但镜头的手持漂浮和摆动写在规划里，这个旋钮不会重新规划，所以那部分不更新 | 中（只生效一半） |
| A3 | 旋钮「进场时长」 | 入场速度立即改变，但字提前出现的时间和规划好的入场位移要等下次重新规划才更新 | 中（只生效一半） |
| A4 | 旋钮「运镜速度」 | 它同时调整的「漂移幅度」没有任何程式读取（镜头的漂移速度是写死的），预设里的 drift 数值也都没用 | 低（部分失效） |
| A5 | 残留项目 | 已移除功能的「转向区间」（`m.flip`、重新规划表里的 `flip`）、介面文字 `m.*` 一整组、旧主题名称（炫酷、电子、温柔、雾光、墨白、切割、平滑）都没有使用 | 低（清理） |
| A6 | 重新规划的分级 | 旋钮表标了「只需重算镜头」「只需重算触发」等不同等级，但实际上任何需要重算的旋钮都整个重新规划（排版＋镜头＋触发），浪费时间 | 中（效能） |
| A7 | 特效自己的参数 | 光点数量、字环数量与样式、字形纹样对比、反色几何入场：都有被读取 | 正常 |
| A8 | 全域设定 | 各设定项都有对应的程式使用 | 正常 |
| A9 | 背景专属特效 | 碎玻璃、门框、背景线条、立体线条、碎块在任何背景下都会画，不是只有哥特、唱片才有效 | 需修正方案：风格系统方案原本打算「只在对应背景显示」，这会拿掉其实能用的选项，改为分组标示即可 |

## 二、图层逻辑

目前每一帧的绘制顺序：

| 顺序 | 内容 | 跟随镜头的方式 |
|---|---|---|
| 1 | 背景，以及背景层特效（光点、羽毛、节拍光环、网格、频谱、唱片系列、碎玻璃板、字形纹样） | 镜头的旋转和缩放，加上一半的平移视差 |
| 2 | 闪光（整片叠色） | 固定在画面上 |
| 3 | 帷幕开启时的底色 | 固定 |
| 4 | 歌词后方：歌词框线、字环 | 跟着字的投影 |
| 5 | 歌词（含动态残影） | 投影，依远近受力 |
| 6 | 歌词前方：星星 | 投影 |
| 7 | 前景：哥特锁链、几何前景、碎玻璃碎片、前景羽毛 | 各自处理，多数跟着画面晃动 |
| 8 | 反色闪光 | 固定 |
| 9 | 模糊转场 | 固定 |
| 10 | 闲置点、字幕、开场、片尾卡、结尾淡出到背景色 | 固定 |
| 11 | 帷幕 | 固定，不受震动影响 |
| 12 | 萤幕特效：颗粒、暗角、扫描线、色散、故障、反色几何 | 固定，盖在所有东西上，包括帷幕 |

整体顺序合理，也符合之前的要求（帷幕在萤幕特效之下、不受震动）。不一致的地方：

| # | 问题 | 建议 |
|---|---|---|
| B1 | 背景层特效跟随镜头的方式不一致：背景、封面、地面、粒子、唱片系列会跟着平移视差；节拍光环和碎玻璃板只跟旋转缩放，不跟平移 | 统一由背景层一次套用视差，各特效不自己处理 |
| B2 | 「反色几何」放在萤幕层，会连字幕、片尾卡、帷幕一起反色 | 移到前景层（字幕之前）；或确认这是刻意的 |
| B3 | 结尾淡出到背景色之后才画萤幕特效，所以画面全黑后颗粒、扫描线、暗角还在 | 若要「完全结束」，萤幕特效也跟着淡出 |
| B4 | 粒子类分散在三层：光点在背景层，羽毛分背景和前景两层，星星在歌词前方；这是设计，但没有文件说明 | 在架构文件里列一张「特效 → 图层 → 跟随方式」表；风格系统的特效分组照这张表 |
| B5 | 依远近受力只作用在歌词世界（歌词、星星、框线、字环），背景层是统一的一半视差 | 合理，维持 |

## 三、预设、镜头与两个场景是否生效

用测试歌词，在 6 种镜头 × 3 种歌词类型下各规划一次：

| 项目 | 结果 |
|---|---|
| 俐落：每次抵达的顿挫 | 有（约 80～100 次） |
| 圆舞：弹簧踢动 | 有（约 55 次） |
| 特写：较多快速模糊转场 | 有（10～11 次，是其他镜头的两倍） |
| 悬停：停在词组中间 | 有 |
| 置中：三列一组、每组转场 | 有 |
| 滑行：往左的行用悬停取景 | 有 |
| 圆心：不排竖排 | 有 |
| 疾走场景 | **有效**：快而密的歌词 10 句中有 9 句触发，所有镜头都会（置中除外，这是设计） |
| 滚筒场景 | **有效**：重复的词会滚动；但两次重复之间的时间不够完成一次滚动（约 1.5 秒）时就不滚，所以唱得很快的重复不会转，看起来像「没触发」 |
| 歌词框线 | 特写镜头下自动框线关闭（设计如此），`$1` 手动框线仍会画 |

近几次修改没有让任何镜头或场景失去触发。两个需要注意的地方：

- **没有疾走场景的测试**：之前没有任何测试检查疾走场景，以后改动可能悄悄弄坏它，应补上。
- **滚筒的时间门槛**：快速重复不滚动是刻意的，但如果你希望快速重复也有效果，可以改成「时间不够就滚小一点、快一点」。

## 四、逻辑错误与调参卡顿

### D1：调参时每动一下就整个重新规划（确认，就是你怀疑的问题）

- 滑杆每一次数值变化都会立即套用，不是放开滑鼠后才算。
- 会重新规划的旋钮（运镜速度、力度、转向幅度、空间纵深、字号、触发灵敏度、字形纹样频率）以及多数下拉选单，每动一下就在主执行绪上整个重新规划一次。这期间画面和介面都停住。
- 实测一次重新规划的时间（测试歌词 48 句）：

| 镜头 | 一次重新规划 |
|---|---|
| 特写 | 1.30 秒 |
| 俐落 | 0.90 秒 |
| 滑行 | 0.64 秒 |
| 圆舞 | 0.52 秒 |
| 悬停 | 0.27 秒 |
| 置中 | 0.06 秒 |

- 拖一下滑杆通常会产生十几个数值变化，所以会卡好几秒。
- 每次重新规划后，还会重新烘焙字形快取，整个面板也会重新绘制。
- 2.7 加入「镜头自己加的转场带回排版重排，最多三轮」之后，规划时间比以前长。

### D2：歌词微调和片尾长度滑杆会同时跑好几十次完整重建（严重）

- 这两个滑杆每动一下就从头重建：重新解析歌词、分词、等字体、重新规划。
- 重建时会等字体载入（最多 1.2 秒）。等待期间，每一帧都会再启动一次新的重建，没有「已经在重建就不要再开」的保护，所以拖动时会同时堆起几十个重建。
- 换字体、套用预设、编辑无歌词歌曲的资讯也走同一条路，只是不是连续触发，影响较小。

### D3：拖动颜色时

每一步都会产生新颜色的大字点阵图。快取有上限，不会无限增长，但拖动期间会比较吃力。

### 修正方向

| 问题 | 做法 |
|---|---|
| D1 | 只影响画面的参数（光晕、律动、漂浮的字本身、入场速度、残影、颜色）拖动时即时预览；需要重新规划的参数放开滑鼠后才重算，拖动期间只更新数字 |
| D1、A6 | 依旋钮实际影响的范围只重算需要的部分，例如运镜速度只重算镜头 |
| D1 | 长期：规划移到背景执行绪，不挡画面；并缩短多轮重排的时间 |
| D2 | 同一时间只跑一次重建，新的变更合并到下一次；歌词微调只需重新规划，不必重新解析和分词 |
| A1–A3 | 让色散、故障开关和漂浮感、进场时长这两个旋钮触发它们需要的重算 |
