# G5 曲库条目、音频内容与缓存

G5 在 `4.0.0-alpha.4` 的既有应用资料上运作。G1 的程序版本、资料代次和目录所有权规则维持原样。曲库索引自身从 `library/db.json` v1 升级至 v2。启动先原子保存一次 `db.v1.json`，再用同步落盘的同目录临时文件替换索引。中断后可从仍完整的 v1 索引继续。遇到损坏、外链或未知版本会报告错误并保留原件。收藏、歌单、文件路径、播放统计、`overrides` 和按既有 `TrackId` 存放的 `songs/*.json` 都保留。v1 遗留条目以原路径、大小和 mtime 匹配为一次性继承依据。旧索引缺少足以追溯迁移前同大小、同 mtime 替换的内容证据，历史缓存仍需重建。

## 条目与关联

`TrackId` 代表条目。新 ID 来自 128 位随机数，与文件内容、路径及平台 ID 独立。两份完全相同的文件可拥有独立歌单关系、播放统计、外观及歌词偏移，同时共享音频分析。路径没变且存储快照仍匹配时不重读完整音频。同卷移动或重命名通过文件系统身份寻找旧条目，并对变化后的快照验证完整内容后再接回原 ID。只改标签、歌词或封面的文件可通过内容相等接回原条目。

同路径内容替换、多个候选、首次验证前已经移动以及文件身份不可靠的跨卷变动，均保留失联条目和用户记录。未能证实关联的新文件获得独立 ID。曲库 IPC 可报告失联或内容变化条目，正常视图和媒体路由只使用已连接条目。该阶段采用保守关联，跨卷重新关联及手动确认界面留到明确授权的后续任务。音频重新编码或剪切产生新的内容身份。将旧条目的资料接到新内容需要可追踪的编辑事务或人工确认。

## `audio-sha256-v1`

原生 `--audio-identity` 使用锁定的 Symphonia 0.6.1，读取所有可识别音轨的编码包，无需解码 PCM。每轨记录音频配置、声道、时基、起点、编码延迟和填充，按顺序输入全部包的时间、时长、裁剪和负载。数值字段采用小端，变长字段带长度，轨结果另带包数和默认音轨标记。容器名称、上述 SHA-256 结果及 MP4 音频时序补充再进入带版本的 SHA-256 外层。修改编码包中的字节或交换包顺序会反映在内容 ID 中。

MP4 使用解复用器实际解析后的音频样本顺序与配置，只对音轨补充电影时基、编辑列表、音轨标志、采样描述类型、时序和样本分组。`mdat` 中视频、封面和其他附属媒体不进入音频指纹。音频样本描述必须单一，复杂多描述文件暂保留普通可播放行为并停用可复用身份。G4R 的 `mdat` 和标签清单验证仍负责写回保护，有不同用途。WebM 等容器的重封装可能实际改变包时序，此时内容 ID 可以改变。

文件重开以大小、mtime、ctime 和文件系统身份重新确认来源快照。单个后台原生任务限时运行，Windows 使用后台资源调度优先级，并在两首之间让出 I/O。扫描发现的新版本会撤销同路径的过期任务。文件缺失、不可识别、被保护或快照不一致时不复用持久化分析。普通输出与 Hi-Fi 不等待 SHA-256 才起播。开发和安装构建应使用配套原生二进制。 [Windows 后台资源调度](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setpriorityclass)

## 缓存与独立版本

指纹失败按原文件快照做两次后台退避重试，其他已就绪曲目可以先处理。重试耗尽后保留未验证状态，手动重新扫描或下次启动可重新验证。同一快照的失败不会开放分析写入。退避等待期间发现新的快照时撤销旧工作。

| 数据 | 持久化语义 |
| --- | --- |
| 音频内容 | 完整 SHA-256 证明和文件快照存于索引。普通播放依然按 Range 读取，无全曲 PCM 持久化。 |
| 节奏 | `AudioContentId + 算法版本 + 引擎、鼓轨、运行时、设备选项`。gzip 信封包含键、版本和正文 SHA-256，经原子写入后登记。读回校验失败时使该条目重新进入分析队列。 |
| 响度 | 内容 ID 与独立算法版本。相同音频共用，曲目统计及显示设置各自保存。 |
| 歌词／元数据 | 各自递增修订。标签或侧车歌词变动与标题、封面变动分别记录。原始歌词和用户编辑保留格式与结构，按 TrackId 保存字段来源。仓库当前没有在线歌词／翻译或视觉计划的持久化缓存实现。 |
| 视觉 | G5 提供条目、歌词、元数据和音频内容修订。后续以实际依赖的版本、风格和渲染能力作为键，无需在 G5 中缓存整份场景。 |
| 在线与下载 | 来源引用、匹配关系和档位有持久化形状。查询缓存、短期媒体租约、授权、下载暂存及适配器实现在 G5.5 接入。 |

写分析前从主进程取得当前内容、文件快照、分析参数及清理代次。写回时重新校验，清理、重分析、文件替换和参数变化后的旧任务无法把结果挂到新状态。旧抽样指纹不足以证明历史节奏及响度实际来自哪段音频，迁移保留旧缓存文件供回查，运行时从已验证输入渐进生成新缓存。缓存清理只删除派生数据和缩略图。长期容量和分析任务的更细配额由 G6 接续。

在线类型位于 `src/core/media-identity.ts`。远端曲目、录音匹配、音质档位、已验证的媒体导入引用和活动租约分别建模。平台能力按适配器声明，租约内的 URL 和授权不进入索引。 [在线整合决策](ONLINE-RESEARCH.md)
